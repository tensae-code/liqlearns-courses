# Lesson plan — Drawing an ERD

**Course:** Computer Science and ICT · **Title:** Databases · **Lesson:** Drawing an ERD
**Place in the curriculum:** Unit 3 — Database Management (Ethiopia Grade 11 Information Technology), in the Databases title of the Computer Science and ICT course. The ladder is the recommended order, never a forced one.
**The one thing this lesson teaches:** an ERD draws a data model with three shapes: entities as rectangles, attributes as ellipses, and relationships as lines joining entities with the relationship name written on the line — and a case is solved by finding the entities first, then the attributes, then the relationships.
**This lesson's own level:** it is a doing-lesson. It stands on Entities, attributes and relationships and on the three relationship types — this lesson draws them.

A lesson plan also says **what goes on top of the lesson**: at the exact places marked below, the lesson page carries an add-on — an image, a GIF, a video, an audio. ## Sub lessons
The parts of this lesson, in order — the list the learner sees from the start, locked ahead, each opening when the one before it is proved:

1. **The three shapes** — an ERD is the popular visual way to draw a data model: entities as rectangles, attributes as ellipses, relationships as lines with the name written on the line
2. **The worked example — student borrows book** — the student entity (student ID, name, age, address) joined to the book entity (book ID, title, publication year) by the “borrows” relationship; the practice task is a teacher–schedule ERD
3. **Solving a case study (teacher guide — evidence)** — the guide's solved case: Product, Customer and Order — a customer makes one or many orders; an order is for one or more products; a product may have no order or belong to only one order

Gate pool: all questions of the sub lesson — no hardness ranking is written in questions/, so the sub lesson's whole question set is the gate pool.

## Before this lesson
- Recommended first: Entities, attributes and relationships; One-to-one, one-to-many, many-to-many. Recommended, never forced.

## What the learner can do when it ends
1. Name the ERD's three components and the shape for each: rectangle, ellipse, labelled line.
2. Draw the book's worked ERD: student (student ID, name, age, address) — borrows — book (book ID, title, publication year).
3. Set up the book's practice: a teacher–schedule ERD.
4. Solve a case the teacher-guide way (evidence): entities first, then attributes, then relationships — Product, Customer, Order with its three relationship rules.

## What you need
Paper and a pencil — an ERD is learned by drawing it. A ruler helps the lines.

## If the learner is stuck
- Draws attributes as rectangles → attributes are always ellipses; only entities get rectangles.
- Forgets the name on the line → an unlabelled line says nothing; the relationship's name (its verb) must sit on the line.
- Starts a case by drawing lines → follow the solving order: entities, then attributes, then relationships.
