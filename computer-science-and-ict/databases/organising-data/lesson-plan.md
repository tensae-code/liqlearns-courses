## Sub lessons
The parts of this lesson, in order — the list the learner sees from the start, locked ahead, each opening when the one before it is proved:

1. **What organising data means** — **Organising data** is arranging it by a chosen structure: the same kind of value in the same place, every record in the same shape. Its working form is the **table**: rows as records (one pupil, one book, one sale), columns as **fields** (name, date, amount — one kind per column), each cell holding one value of its column's kind. Organised data can be searched, sorted, counted and compared; unorganised data can only be read, slowly, by a human, once.
2. **The organising decisions** — Organising is decisions: **what is a record** (the unit each row stands for), **which fields** (only what the questions need — every extra field is collecting and guarding forever), **what each field holds** (its type and its allowed shape — dates written one way, names spelled one way), and **what identifies each record** (the key that keeps two same-named pupils distinct). Jordan's Grade 10 lesson stands at the database title's door: a database is organised data with these decisions enforced by the machine — which is why the decisions are taught before the software.
