# Designing a Relational Database — multiple choice

Pick the one right answer.

**1. (Sub lesson 1) Where does design start?**
a) From the need — what the database must hold and what questions it must answer  b) The kinds of thing the database is about — Pupil, Book, Loan  c) The facts kept about an entity — a pupil's name, class, date of birth  d) Only if the need asks for it
**Answer: a) From the need — what the database must hold and what questions it must answer**

**2. (Sub lesson 1) What are entities?**
a) The facts kept about an entity — a pupil's name, class, date of birth  b) The kinds of thing the database is about — Pupil, Book, Loan  c) Only if the need asks for it  d) A question the database must answer
**Answer: b) The kinds of thing the database is about — Pupil, Book, Loan**

**3. (Sub lesson 1) What are attributes?**
a) Only if the need asks for it  b) A question the database must answer  c) The facts kept about an entity — a pupil's name, class, date of birth  d) The attribute (or added ID) that picks out one record from all others
**Answer: c) The facts kept about an entity — a pupil's name, class, date of birth**

**4. (Sub lesson 1) When does an attribute belong in the design?**
a) A question the database must answer  b) The attribute (or added ID) that picks out one record from all others  c) The relationships between entities, with their cardinality  d) Only if the need asks for it
**Answer: d) Only if the need asks for it**

**5. (Sub lesson 1) What should every table and column trace back to?**
a) A question the database must answer  b) The attribute (or added ID) that picks out one record from all others  c) The relationships between entities, with their cardinality  d) One per entity, attributes as columns, keys in place
**Answer: a) A question the database must answer**

**6. (Sub lesson 2) What is a primary key?**
a) The relationships between entities, with their cardinality  b) The attribute (or added ID) that picks out one record from all others  c) One per entity, attributes as columns, keys in place  d) Foreign keys
**Answer: b) The attribute (or added ID) that picks out one record from all others**

**7. (Sub lesson 2) What else is stated before tables are drawn?**
a) One per entity, attributes as columns, keys in place  b) Foreign keys  c) The relationships between entities, with their cardinality  d) A guess the data will later pay for
**Answer: c) The relationships between entities, with their cardinality**

**8. (Sub lesson 2) How are tables then drawn?**
a) Foreign keys  b) A guess the data will later pay for  c) From the need — what the database must hold and what questions it must answer  d) One per entity, attributes as columns, keys in place
**Answer: d) One per entity, attributes as columns, keys in place**

**9. (Sub lesson 2) What carries the relationships in the tables?**
a) Foreign keys  b) A guess the data will later pay for  c) From the need — what the database must hold and what questions it must answer  d) The kinds of thing the database is about — Pupil, Book, Loan
**Answer: a) Foreign keys**

**10. (Sub lesson 2) What are tables drawn before entities and keys are understood?**
a) From the need — what the database must hold and what questions it must answer  b) A guess the data will later pay for  c) The kinds of thing the database is about — Pupil, Book, Loan  d) The facts kept about an entity — a pupil's name, class, date of birth
**Answer: b) A guess the data will later pay for**
