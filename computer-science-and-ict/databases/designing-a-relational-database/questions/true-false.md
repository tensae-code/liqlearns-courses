# Designing a Relational Database — true-false

Say whether each statement is true or false.

**1. (Sub lesson 1) True or false: the answer to "Where does design start?" is: From the need — what the database must hold and what questions it must answer**
**Answer: True**

**2. (Sub lesson 1) True or false: the answer to "What are entities?" is: The facts kept about an entity — a pupil's name, class, date of birth**
**Answer: False** — The kinds of thing the database is about — Pupil, Book, Loan

**3. (Sub lesson 1) True or false: the answer to "What are attributes?" is: The facts kept about an entity — a pupil's name, class, date of birth**
**Answer: True**

**4. (Sub lesson 1) True or false: the answer to "When does an attribute belong in the design?" is: A question the database must answer**
**Answer: False** — Only if the need asks for it

**5. (Sub lesson 1) True or false: the answer to "What should every table and column trace back to?" is: A question the database must answer**
**Answer: True**

**6. (Sub lesson 2) True or false: the answer to "What is a primary key?" is: The relationships between entities, with their cardinality**
**Answer: False** — The attribute (or added ID) that picks out one record from all others

**7. (Sub lesson 2) True or false: the answer to "What else is stated before tables are drawn?" is: The relationships between entities, with their cardinality**
**Answer: True**

**8. (Sub lesson 2) True or false: the answer to "How are tables then drawn?" is: Foreign keys**
**Answer: False** — One per entity, attributes as columns, keys in place

**9. (Sub lesson 2) True or false: the answer to "What carries the relationships in the tables?" is: Foreign keys**
**Answer: True**

**10. (Sub lesson 2) True or false: the answer to "What are tables drawn before entities and keys are understood?" is: From the need — what the database must hold and what questions it must answer**
**Answer: False** — A guess the data will later pay for
