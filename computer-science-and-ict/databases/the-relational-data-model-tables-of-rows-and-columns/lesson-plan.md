# Lesson plan — The relational data model — tables of rows and columns

**Course:** Computer Science and ICT · **Title:** Databases · **Lesson:** The relational data model — tables of rows and columns
**Place in the curriculum:** Unit 3 — Database Management (Ethiopia Grade 11 Information Technology), in the Databases title of the Computer Science and ICT course. The ladder is the recommended order, never a forced one.
**The one thing this lesson teaches:** the relational model represents data as two-dimensional tables called relations: each row is a record (a tuple) holding one unique instance, each column is an attribute (a field) — and a shared attribute placed in one relation links it to another.
**This lesson's own level:** it stands on the data-model lessons before it in this title: entities and attributes, drawn in the ERD, now become tables.

## Sub lessons
The parts of this lesson, in order — the list the learner sees from the start, locked ahead, each opening when the one before it is proved:

1. **Relations — tables with rows and columns** — the relational model represents data as two-dimensional tables called relations; each row is a record (tuple) holding one unique instance; each column is an attribute (field)
2. **The worked student relation — and linking relations** — the student relation lists ID, name, sex, grade and address; a whole model is a collection of relations, their attributes and their relationships, with a shared attribute placed in one relation to link it to another
3. **The Country–City worked join (teacher guide — evidence)** — the guide fully works the join: the linking attribute identified, the fields counted, the Kenyan cities picked out, and a joined country–city–population table of nine cities across Ethiopia, Egypt, Kenya and Sudan

4. **Grade 12 — the RDBMS frame, and fields and records in Ethiopian examples** — the Grade 12 frame: an RDBMS creates, maintains and controls access; a student entity's five attributes; (teacher guide — evidence) Ethiopian field/record example sets — patient fields, Person/Book/Sales fields, one full Student row, field values from a book title to a cost in birr

Gate pool: all questions of the sub lesson — no hardness ranking is written in questions/, so the sub lesson's whole question set is the gate pool.

## Before this lesson
- Recommended first: Entities, attributes and relationships; Drawing an ERD. Recommended, never forced.

## What the learner can do when it ends
1. Say what a relation is: a two-dimensional table in the relational model.
2. Use the paired words: a row is a record, also called a tuple; a column is an attribute, also called a field.
3. Read the worked student relation: ID, name, sex, grade, address — one row per student.
4. Say how relations link: a shared attribute placed in one relation links it to another.
5. Follow the Country–City worked join (teacher evidence): the linking attribute joins two tables into one answer table.

## If the learner is stuck
- Mixes row and column names → a row runs across and holds one instance; a column runs down and holds one property for all.
- Thinks each table stands alone → a shared attribute placed in one relation is what links it to another; that link is the model's point.
