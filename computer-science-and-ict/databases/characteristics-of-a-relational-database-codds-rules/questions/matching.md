# Characteristics of a Relational Database — Codd's Rules — matching

Match each item on the left with the one it belongs to on the right.

**1. (Sub lesson 1) Who wrote the rules for a true RDBMS?** → **Edgar Codd, the relational idea's inventor**

**2. (Sub lesson 1) How must all information be held, by the rules?** → **As values in tables — nothing hidden in pointers**

**3. (Sub lesson 1) How is every value reachable?** → **By table name, key and column name**

**4. (Sub lesson 1) How must nulls be handled?** → **Systematically — by rule, not by accident**

**5. (Sub lesson 1) What one language must do everything?** → **The comprehensive language — SQL**

**6. (Sub lesson 2) Name the kind of systems on the book's standard list.** → **The RDBMS systems organisations actually run, desktop to national scale**

**7. (Sub lesson 2) Name two promises the rules let a buyer test.** → **Data independence from programs, and system-enforced integrity**

**8. (Sub lesson 2) What must have no back doors around it?** → **The database language**

**9. (Sub lesson 2) What outlives what, when the rules hold?** → **The data outlives the programs**

**10. (Sub lesson 2) Is a useful non-relational system 'wrong'?** → **No — useful, but not fully relational**
