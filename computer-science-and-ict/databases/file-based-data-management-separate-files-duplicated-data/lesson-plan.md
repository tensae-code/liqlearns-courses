# Lesson plan — File-based data management — separate files, duplicated data

**Course:** Computer Science and ICT · **Title:** Databases · **Lesson:** File-based data management — separate files, duplicated data
**Place in the curriculum:** Unit 3 — Database Management (Ethiopia Grade 11 Information Technology), in the Databases title of the Computer Science and ICT course. The ladder is the recommended order, never a forced one.
**The one thing this lesson teaches:** in the file-based approach, data is stored in separate files with no explicit relationships — each department keeps its own files, managed by its own program — and that is why copies drift, data turns inconsistent and redundant, and the whole organisation's data is very hard to pull together.
**This lesson's own level:** it opens the Databases title. It stands on everyday office experience only — files in folders, one per job.

## Sub lessons
The parts of this lesson, in order — the list the learner sees from the start, locked ahead, each opening when the one before it is proved:

1. **Separate files, each with its own program** — data lives in separate files with no explicit relationships; each file is managed by its own application program, and each department keeps its own files
2. **Duplication — copies that drift apart** — the same data kept in more than one file is duplicated; copies are never linked, so they drift out of step — data becomes inconsistent and redundant
3. **The whole organisation's data — and its security** — pulling together all the organisation's data from separate files is very difficult; teacher evidence adds that one organisation-wide security procedure becomes difficult and expensive

Gate pool: all questions of the sub lesson — no hardness ranking is written in questions/, so the sub lesson's whole question set is the gate pool.

## What the learner can do when it ends
1. Say how data is stored in the file-based approach: separate files, no explicit relationships, each file managed by its own application program.
2. Say why changing data can mean changing the program — and changing the program can mean changing the file structure.
3. Explain, with the employee-records example, how duplicated copies drift out of step and make data inconsistent and redundant.
4. Say why pulling together the whole organisation's data is very difficult in this approach.
5. Name the third limitation (teacher evidence): one organisation-wide security procedure is difficult and expensive when data is scattered.

## What you need
Paper and a pencil. Nothing else.

## If the learner is stuck
- Thinks duplication means a backup → a backup is a copy kept to restore the same data; duplication here means two live copies, each changed on its own, with no link between them.
- Cannot see why the program matters → the file's shape is the shape its program expects; change the program and the file structure may have to change with it.
