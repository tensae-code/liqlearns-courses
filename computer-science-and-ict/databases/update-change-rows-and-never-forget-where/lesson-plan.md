# Lesson plan — UPDATE — change rows, and never forget WHERE

**Course:** Computer Science and ICT · **Title:** Databases · **Lesson:** UPDATE — change rows, and never forget WHERE
**Place in the curriculum:** Unit 3 — Database Management System (Ethiopia Grade 12 Information Technology), in the Databases title of the Computer Science and ICT course. The ladder is the recommended order, never a forced one.
**The one thing this lesson teaches:** UPDATE changes values in existing rows — SET names the new values, WHERE chooses the rows — and an UPDATE with no WHERE changes every row in the table.
**This lesson's own level:** it stands on INSERT: records exist; this lesson changes them in place, adding and removing none.

## Sub lessons
The parts of this lesson, in order — the list the learner sees from the start, locked ahead, each opening when the one before it is proved:

1. **The form — SET and WHERE** — the UPDATE form: SET new values, WHERE chooses rows; the salary-below-10,000 raise
2. **Widening the WHERE — one statement, many rows** — one statement changing a whole group (all female teachers); (teacher guide — evidence) single-record updates by key
3. **The warning — no WHERE means every row** — the warning: no WHERE updates every row; the guide's deliberate all-rows grade-level example

## Before this lesson
- Recommended first: INSERT examples — full rows and partial rows. Recommended, never forced.

## What the learner can do when it ends
1. Write an UPDATE with SET and WHERE.
2. Change a whole group with one widened WHERE.
3. Change one record chosen by its key.
4. Refuse — or deliberately confirm — a no-WHERE update.

## If the learner is stuck
- Thinks UPDATE adds rows → it changes existing rows only; INSERT adds, DELETE removes.
- Writes SET and forgets WHERE → the read-aloud habit: no WHERE is spoken, no UPDATE is run, until 'every row' is confirmed as the intent.
