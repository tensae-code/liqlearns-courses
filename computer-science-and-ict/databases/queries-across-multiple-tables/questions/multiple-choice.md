# Queries across multiple tables — multiple choice

Pick the one right answer.

**1. (Sub lesson 1)** Each needed table is added with Show Table and the —
a) Add button  b) Create button  c) Primary Key button
**Answer: a)** — Show Table, then Add, for each table.

**2. (Sub lesson 2)** The relationship is established by dragging —
a) a table onto the grid  b) the parent table's primary-key field onto the matching field of the child table  c) a result row onto a table
**Answer: b)** — primary key of the parent onto the matching field of the child.

**3. (Sub lesson 3)** In the book's example, subject and grade are taken from —
a) Student  b) Teacher  c) Grade
**Answer: c)** — the Grade table; name comes from Student, teacher name from Teacher.

**4. (Sub lesson 3)** After picking the fields, the query is —
a) deleted  b) saved with a name, and the combined results viewed  c) printed only
**Answer: b)** — saved with a name; view the combined results.

**5. (Sub lesson 4)** A two-table SELECT is meaningful only if the tables are —
a) in the same folder  b) linked  c) both empty  d) both dropped
**Answer: b) linked** — unlinked, the result is meaningless.

**6. (Sub lesson 4)** Columns in a two-table query are written —
a) with nicknames  b) qualified as table.column  c) in capitals only  d) without names
**Answer: b) qualified as table.column** — qualification avoids name clashes.

**7. (Sub lesson 4)** The WHERE in a join equates —
a) two primary keys  b) the first table's primary key with the second's foreign key  c) two dates  d) the table names
**Answer: b) the first table's primary key with the second's foreign key** — PK = FK is the join condition.

**8. (Sub lesson 4)** Adding Semester = 'I' to the worked join —
a) drops CourseOffering  b) filters the joined output to first-semester courses only  c) sorts by semester  d) creates a third table
**Answer: b) filters the joined output to first-semester courses only** — a second criterion narrows the joined result.
