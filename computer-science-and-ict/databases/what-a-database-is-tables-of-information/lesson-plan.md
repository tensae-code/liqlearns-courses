## Sub lessons
The parts of this lesson, in order — the list the learner sees from the start, locked ahead, each opening when the one before it is proved:

1. **A database — information with a shape** — A **database** is information kept in an organised shape a computer can work on: not a pile of notes but **tables** — rows of records, columns of fields — holding one kind of thing each, under rules that keep it consistent. The shape is the point: because records share a form, the program can **search** the whole store in a blink, **sort** it any way, and trust that every record answers the same questions.
2. **Why a program connects to one** — A program **connects** to a database when the information must **outlive the program's run** and be **shared**: the records stay on disk when the program closes, and many programs — or many users — work on the same single store instead of private copies that drift apart. Kuwait opens its final database book here because the VB year that follows is exactly this: forms and grids and reports, all of them windows onto tables that live apart from any one program.
