**The one thing this lesson teaches:** Data inside a database is organised as a ladder: a character is one letter or digit; characters together make a field (one fact, like a name); fields about one person or thing make a record; records of the same kind make a table; and related tables together make the database — each level is built out of the level below it.

## Sub lessons
The parts of this lesson, in order — the list the learner sees from the start, locked ahead, each opening when the one before it is proved:

1. **The ladder — character, field, record, table** — The bottom rungs: a character is a single letter, digit or symbol — the smallest piece. Characters join to form a field, one single fact such as a name or an admission number. All the fields belonging to one person or thing form that person's record. All the records of the same kind, kept together, form a table (a file of records).
2. **The top of the ladder — the database, and why the ladder matters** — A database is a collection of related tables kept together and managed by a DBMS: the pupils table, the teachers table, the fees table of one school. The ladder matters because programs work level by level — you search for a record, change one field, add a character at a time — and because mixing levels up (two facts in one field) breaks searching and sorting.

## What the learner can do when it ends
1. Name the levels of the data hierarchy in order, from character up to database.
2. Break one real example (a student's school record) into its characters, fields, records, table and database.
3. Say what is stored at each level and give an example of each.
4. Explain why the levels matter: a database program searches and updates data level by level.

## What you need
Paper and a pencil. One real form or record card (a school report, a clinic card) serves as the example.
