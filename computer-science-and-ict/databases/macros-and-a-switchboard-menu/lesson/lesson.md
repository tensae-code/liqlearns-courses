# Macros and a Switchboard Menu

## Do it first

A database of tables, forms and reports is still a workshop, not a system, until an ordinary user can run it without knowing Access. Malaysia's database chapter finishes the build with macros and a switchboard. In this lesson you give a database its face.

## Sub lesson 1 — Macros — actions at a click

A **macro** is a saved list of **actions** that runs as one: open a form, run a query, print a report, close a window. A macro is built by choosing its actions from a list — no code is written — and it is attached to an **event**, most often a button's click: the button labelled 'Enter Marks' runs the macro that opens the marks form at a new record. Macros are how the database's separate pieces are wired into behaviour a user can trigger without touching the design.

In your mind's eye: macros — actions at a click.

## Sub lesson 2 — The switchboard — the system's menu

A **switchboard** is a special form that works as the system's **main menu**: it opens when the database opens, and its buttons — each running a macro — offer the system's whole work in the user's own words: Enter Data, Run Reports, Print Lists. The switchboard hides the workshop (tables, design views) behind one calm page. Malaysia's completed database project is judged by this face: if a teacher who has never seen Access can do the system's jobs from the switchboard alone, the system is finished; if not, it is still a workshop.

In your mind's eye: the switchboard — the system's menu.
