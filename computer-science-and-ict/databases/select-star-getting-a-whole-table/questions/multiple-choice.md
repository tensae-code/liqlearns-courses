# SELECT * — getting a whole table — multiple choice

Pick the one right answer.

**1. (Sub lesson 1)** SELECT * FROM COURSE; returns —
a) only the key column  b) all records and all columns  c) all records, key column only  d) the table's design
**Answer: b) all records and all columns** — * means all columns; no WHERE means all rows.

**2. (Sub lesson 1)** The asterisk gives the same result as —
a) a WHERE clause  b) listing every field by name  c) ORDER BY  d) a form-2 insert
**Answer: b) listing every field by name** — it is the full list, shortened.

**3. (Sub lesson 1)** Use * when —
a) one column is wanted  b) all fields are wanted  c) rows must be filtered  d) sorting matters most
**Answer: b) all fields are wanted** — that is the book's recommendation.

**4. (Sub lesson 2)** A field named with one wrong letter —
a) still works  b) does not produce the expected output  c) renames the field  d) is corrected by Access silently here
**Answer: b) does not produce the expected output** — names must be spelled exactly as in the table.

**5. (Sub lesson 2)** On a many-column table, * is good practice because —
a) it runs on paper  b) listing every field invites naming errors  c) it sorts the output  d) it filters rows
**Answer: b) listing every field invites naming errors** — the guide's stated reason.

**6. (Sub lesson 2)** SELECT * with a WHERE clause —
a) is invalid  b) returns all columns but only matching rows  c) ignores the WHERE  d) drops the table
**Answer: b) returns all columns but only matching rows** — * governs columns; WHERE governs rows.
