# Mapping an ERD to a Relational Schema — true-false

Say whether each statement is true or false.

**1. (Sub lesson 1) True or false: the answer to "What does every entity become?" is: A table**
**Answer: True**

**2. (Sub lesson 1) True or false: the answer to "What does every attribute become?" is: The table's primary key**
**Answer: False** — A column of its entity's table

**3. (Sub lesson 1) True or false: the answer to "What does the key attribute become?" is: The table's primary key**
**Answer: True**

**4. (Sub lesson 1) True or false: the answer to "How is a multivalued attribute mapped?" is: A home in the schema, or a stated reason why not**
**Answer: False** — As a table of its own — the key plus one value per record

**5. (Sub lesson 1) True or false: the answer to "After the straight mapping, what must every part of the ERD have?" is: A home in the schema, or a stated reason why not**
**Answer: True**

**6. (Sub lesson 2) True or false: the answer to "How is a one-to-many relationship carried?" is: As a new table holding both sides' keys as its composite key**
**Answer: False** — By a foreign key — the 'one' side's key placed in the 'many' side's table

**7. (Sub lesson 2) True or false: the answer to "How is a many-to-many relationship mapped?" is: As a new table holding both sides' keys as its composite key**
**Answer: True**

**8. (Sub lesson 2) True or false: the answer to "What else can the new table hold?" is: Every relationship in the ERD must be traceable in the schema — as a foreign key or as a table**
**Answer: False** — The relationship's own attributes — such as a mark

**9. (Sub lesson 2) True or false: the answer to "Give Malaysia's closing check." is: Every relationship in the ERD must be traceable in the schema — as a foreign key or as a table**
**Answer: True**

**10. (Sub lesson 2) True or false: the answer to "What is an ERD, against a schema?" is: A table**
**Answer: False** — A picture; the schema is the buildable design
