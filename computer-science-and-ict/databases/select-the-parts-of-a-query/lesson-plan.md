# Lesson plan — SELECT — the parts of a query

**Course:** Computer Science and ICT · **Title:** Databases · **Lesson:** SELECT — the parts of a query
**Place in the curriculum:** Unit 3 — Database Management System (Ethiopia Grade 12 Information Technology), in the Databases title of the Computer Science and ICT course. The ladder is the recommended order, never a forced one.
**The one thing this lesson teaches:** a SELECT query must settle what data, from where, related how, matching what, sorted how — and it says so in four clauses: SELECT and FROM (required), WHERE and ORDER BY (optional).
**This lesson's own level:** it stands on the SQL families: this is DQL, the asking family, taken apart piece by piece.

A lesson plan also says **what goes on top of the lesson**: at the exact places marked below, the lesson page carries an add-on — an image, a GIF, a video, an audio. The words carry the picture while the course is built and while the AI learns from the books; on the website the real add-on is dropped into that slot and the little explanation stays as the student's guide. ## Sub lessons
The parts of this lesson, in order — the list the learner sees from the start, locked ahead, each opening when the one before it is proved:

1. **What a complete query must settle** — the five things a complete query must settle: data, relations, fields/calculations, criteria, sorting
2. **The four clauses — two required, two optional** — the four clauses — SELECT (required), FROM (required), WHERE (optional), ORDER BY (optional)

Gate pool: all questions of the sub lesson — no hardness ranking is written in questions/, so the sub lesson's whole question set is the gate pool.

## Before this lesson
- Recommended first: SQL — DDL, DML and DQL. Recommended, never forced.

## What the learner can do when it ends
1. State the five things a query must settle.
2. Name SELECT, FROM, WHERE, ORDER BY and their jobs.
3. Say which clauses are required and which optional.
4. Read a query as answers to the settle-questions.

## If the learner is stuck
- Treats WHERE as required → a query without WHERE is valid; it simply takes all rows.
- Forgets FROM → fields live in tables; SELECT without FROM has nowhere to take them from.
