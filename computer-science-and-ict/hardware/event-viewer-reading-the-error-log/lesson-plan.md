# Lesson plan — Event Viewer — reading the error log

**Course:** Computer Science and ICT · **Title:** Hardware · **Lesson:** Event Viewer — reading the error log
**Place in the curriculum:** Unit 5 — Hardware Troubleshooting and Preventive Maintenance (CURRICULUM.md).
**The one thing this lesson teaches:** Windows writes down its own troubles in Event Viewer: every error with its date, time, severity, source, event ID and user — and the troubleshooter reads that log.
**This lesson's own level:** It stands on the beep-code and BIOS lessons: when the machine runs but misbehaves, the log is where its history lives.

A lesson plan also says **what goes on top of the lesson**: at the exact places marked below, the lesson page carries an add-on — an image, a GIF, a video, an audio. Every slot is written as **"a picture of …" in words, plus one little line saying what the student does with it**. The words carry the picture while the course is built and while the AI learns from the books; on the website the real add-on is dropped into that slot and the little explanation stays as the student's guide. GIFs come first where a thing must be shown moving or in steps — a GIF here is 2 seconds.

## Sub lessons
The parts of this lesson, in order — the list the learner sees from the start, locked ahead, each opening when the one before it is proved:

1. **Opening Event Viewer** — Three printed steps through the Windows search box: search, type Event Viewer, open it.
2. **The Windows Logs and what an event records** — Events sit in categories; troubleshooting mostly uses the Windows Logs — Application, System and Security. Each event records what happened, date and time, severity, source, event ID and the user logged in.
3. **Reading one event in full** — Double-click an entry to open its full detail — then, if the fix is still not clear, search the internet for it.

Gate pool: all questions of the sub lesson — no hardness ranking is written in questions/, so the sub lesson's whole question set is the gate pool.
