# Lesson plan — Step 1 — identify the network problem

**Course:** Computer Science and ICT · **Title:** Hardware · **Lesson:** Step 1 — identify the network problem
**Place in the curriculum:** Unit 5 — Maintenance and Troubleshooting (CURRICULUM.md).
**The one thing this lesson teaches:** Network troubleshooting starts by identifying the problem: first whether the fault is inside your local network or outside it, then — gathered, duplicated, asked, and pinned to symptoms and recent changes — exactly what the problem is.
**This lesson's own level:** It stands on Six basic network problems: those are the suspects; this step is how you find which one you actually have.

A lesson plan also says **what goes on top of the lesson**: at the exact places marked below, the lesson page carries an add-on — an image, a GIF, a video, an audio. Every slot is written as **"a picture of …" in words, plus one little line saying what the student does with it**. The words carry the picture while the course is built and while the AI learns from the books; on the website the real add-on is dropped into that slot and the little explanation stays as the student's guide. GIFs come first where a thing must be shown moving or in steps — a GIF here is 2 seconds.

## Sub lessons
1. **Inside or outside your control — the first decision** — the inside/outside decision; the guide's local vs outside definitions with the school lab and telecom examples (teacher evidence).
2. **Identifying the problem itself — six moves** — gather, duplicate, ask, symptoms, changes, define each problem.

Gate pool: all questions of the sub lesson — no hardness ranking is written in questions/, so the sub lesson's whole question set is the gate pool.

## Before this lesson
- Recommended first: Six basic network problems — cable to overload, in this same title. Recommended, never forced — a learner may land on this lesson directly, and it stands alone.

## What the learner can do when it ends
1. Decide inside vs outside control first, with the guide's definitions.
2. Gather information with the available tools.
3. Duplicate the problem, ask users, name symptoms, hunt recent changes, define each problem.

## What you need
Paper and a pencil. A school network to observe, if there is one.
