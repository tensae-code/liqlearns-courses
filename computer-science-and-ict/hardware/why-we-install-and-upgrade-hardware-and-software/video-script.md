# Video script — Why We Install and Upgrade Hardware and Software

The super-simple voice, for the video that rides on top of the lesson (lesson-plan.md, add-on list). Made later, when videos are made; the script is the slot's written form until then.

---

Installing answers a **gap**. New **hardware** is installed when the work needs a capability the machine lacks — a printer where none was, more memory where programs starve, a larger disk where data outgrew the old one. New **software** is installed when a job needs a program the machine does not carry — the accounts package the office just adopted. Fiji's test for any installation is a sentence the installer must be able to finish: *this is being installed so that … can be done, which cannot be done now.*
Upgrading answers a **shortfall**: the capability exists but no longer suffices. Software is upgraded for **new features, fixed faults and security** — and because newer work, files and systems demand newer versions. Hardware is upgraded when **speed, capacity or reliability** fall behind the work — the slow processor, the full disk, the failing drive replaced before it takes data with it. Fiji's caution closes the lesson: every install and upgrade is a change, and change carries risk — so it is done for a stated reason, at a chosen time, with the old state safe to return to.
