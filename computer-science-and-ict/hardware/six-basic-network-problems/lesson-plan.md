# Lesson plan — Six basic network problems — cable to overload

**Course:** Computer Science and ICT · **Title:** Hardware · **Lesson:** Six basic network problems — cable to overload
**Place in the curriculum:** Unit 5 — Maintenance and Troubleshooting (CURRICULUM.md).
**The one thing this lesson teaches:** Slow transmission or no connection usually traces to one of six basic problems: cable, connectivity, out-of-reach, configuration, software, or traffic overload.
**This lesson's own level:** It stands on Network troubleshooting — detect, then fix: these six are the causes that detection hunts first.

A lesson plan also says **what goes on top of the lesson**: at the exact places marked below, the lesson page carries an add-on — an image, a GIF, a video, an audio. Every slot is written as **"a picture of …" in words, plus one little line saying what the student does with it**. The words carry the picture while the course is built and while the AI learns from the books; on the website the real add-on is dropped into that slot and the little explanation stays as the student's guide. GIFs come first where a thing must be shown moving or in steps — a GIF here is 2 seconds.

## Sub lessons
1. **Problems 1–3 — cable, connectivity, out of reach** — the damaged cable; the down port that cuts source from destination; the host beyond the access point's reach.
2. **Problems 4–6 — configuration, software, overload** — wrong configuration and routing; compatibility and version mismatch; a link or device beyond capacity.

Gate pool: all questions of the sub lesson — no hardness ranking is written in questions/, so the sub lesson's whole question set is the gate pool.

## Before this lesson
- Recommended first: Network troubleshooting — detect, then fix, in this same title. Recommended, never forced — a learner may land on this lesson directly, and it stands alone.

## What the learner can do when it ends
1. Name the six basic network problems.
2. Explain each in one line.
3. Match a described fault to its problem.

## If the learner is stuck
- Blames the cable for everything → six causes exist; a wireless range fault is out-of-reach, not cable.
- Mixes connectivity and configuration → connectivity is the physical port down; configuration is a wrong setting, such as routing.
