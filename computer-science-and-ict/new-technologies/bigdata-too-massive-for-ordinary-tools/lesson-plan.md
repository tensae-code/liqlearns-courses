# Lesson plan — Big data — too massive for ordinary tools

**Course:** Computer Science and ICT · **Title:** New Technologies · **Lesson:** Big data — too massive for ordinary tools
**Place in the curriculum:** Unit 2 — Emerging Technologies (CURRICULUM.md).
**The one thing this lesson teaches:** big data is data so massive and complex that typical processing software and ordinary database tools cannot handle it — born of the data explosion, gathered from named sources through a pipeline.
**This lesson's own level:** it stands on the emerging-technologies doorway lesson before it. It needs nothing else.

A lesson plan also says **what goes on top of the lesson**: at the exact places marked below, the lesson page carries an add-on — an image, a GIF, a video, an audio. Every slot is written as **"a picture of …" in words, plus one little line saying what the student does with it**. The words carry the picture while the course is built and while the AI learns from the books; on the website the real add-on is dropped into that slot and the little explanation stays as the student's guide. GIFs come first where a thing must be shown moving or in steps — a GIF here is 2 seconds.

## Sub lessons
The parts of this lesson, in order — the list the learner sees from the start, locked ahead, each opening when the one before it is proved (the gate: README, "Units, Lessons and Sub Lessons (ruled 2026-11-08)"):

1. **What big data is — and where it comes from** — too massive and complex for ordinary tools; computers, the internet and sensors turning the real world into data.
2. **Sources — and the pipeline** — sales, IoT devices, marketing firms, social posts, phone location, surveys; find useful sources, then move the data to storage — Google's reading of searches, location and trends.

Gate pool: all questions of the sub lesson — no hardness ranking is written in questions/, so the sub lesson's whole question set is the gate pool.

## Before this lesson
- Recommended first: the other lessons of this unit. Recommended, never forced.

## What the learner can do when it ends
1. Define big data against ordinary tools.
2. Name six sources of big data.
3. Walk the collection pipeline: identify sources, then move data to storage.
4. Retell the Google worked example.

## What you need
Paper and a pencil. Nothing else.

## The run of the lesson (in order)
1. **Do it first** — Think of every sale, post, photo and phone movement in one city, in one day. Could a normal spreadsheet hold it? Feel why ordinary tools break first. (lesson/lesson.md).
2. **The explanation** — the parts below, in order (lesson/lesson.md).
   - ADD IMAGE [Picture 30101]: a picture of many named sources flowing through a pipeline into one huge store — the student names three sources and traces the flow into the store.

   - ADD AUDIO: a voice reading this lesson's key words aloud — the student listens, then says each word and what it means.
3. **Say it to your companion** — explain the lesson back in your own words (lesson/lesson.md).
   - ADD VIDEO: the script in video-script.md, filmed — the lesson retold in the super-simple voice (made later, when videos are made).
4. **Questions** — from questions/: multiple-choice, true-or-false, fill-in-the-blank, short-answer — served at the learner's level (levels.md).
5. **Hands-on** — hands-on.md.
6. **Do It Yourself** — the doing block at the end of lesson/lesson.md.

## If the learner is stuck
- Thinks big data means 'a big file' → the test is the tool: if typical software and ordinary database tools cannot handle it, it is big data. Mixes the pipeline steps → sources first; you cannot move data you have not chosen.
