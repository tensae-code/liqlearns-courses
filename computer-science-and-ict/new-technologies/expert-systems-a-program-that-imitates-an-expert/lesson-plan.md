# Lesson plan — Expert systems — a program that imitates an expert

**Course:** Computer Science and ICT · **Title:** New Technologies · **Lesson:** Expert systems — a program that imitates an expert
**Place in the curriculum:** Unit 2 — Emerging Technologies (CURRICULUM.md).
**The one thing this lesson teaches:** an expert system imitates a human expert to solve problems experts normally solve; it has three parts — user interface, knowledge base of if–then–else rules, and inference engine — and MYCIN is its famous early example.
**This lesson's own level:** it stands on the Grade 11 Emerging Technologies unit around it. It needs nothing else.

A lesson plan also says **what goes on top of the lesson**: at the exact places marked below, the lesson page carries an add-on — an image, a GIF, a video, an audio. Every slot is written as **"a picture of …" in words, plus one little line saying what the student does with it**. The words carry the picture while the course is built and while the AI learns from the books; on the website the real add-on is dropped into that slot and the little explanation stays as the student's guide. GIFs come first where a thing must be shown moving or in steps — a GIF here is 2 seconds.

## Sub lessons
The parts of this lesson, in order — the list the learner sees from the start, locked ahead, each opening when the one before it is proved (the gate: README, "Units, Lessons and Sub Lessons (ruled 2026-11-08)"):

1. **The user interface** — the door: query in, recommendation out.
2. **The knowledge base** — the experts' if–then–else rules, factual and heuristic.
3. **The inference engine — and MYCIN** — the brain that reasons over the rules; MYCIN at work.

Gate pool: all questions of the sub lesson — no hardness ranking is written in questions/, so the sub lesson's whole question set is the gate pool.

## Before this lesson
- Recommended first: the other lessons of this unit. Recommended, never forced.

## What the learner can do when it ends
1. Define an expert system and name three of its fields.
2. Name the three parts and each part's job.
3. Say what decides how well the system performs.
4. Say what MYCIN does.

## What you need
Paper and a pencil. Nothing else.

## If the learner is stuck
- Mixes knowledge base with inference engine → the base STORES the rules; the engine REASONS with them. Thinks rules are vague → they are written as if–then–else: if this, then that.
