# Lesson plan — First Steps in Educational Robotics

**Course:** Computer Science and ICT · **Title:** New Technologies · **Lesson:** First Steps in Educational Robotics
**Place in the curriculum:** ICT expansion — Djibouti (2026-11-14) — in the title New Technologies on the ICT course ladder (TITLES.md). Built new from Djibouti's *Guide manuel — Informatique, 6ème année*, because no existing lesson gives a first, hands-on initiation into programming a robot as its own lesson.
**The one thing this lesson teaches:** Educational robotics is learning by programming a small robot: you give the robot instructions in an exact order — an algorithm it can follow — run it, watch what it actually does, and fix the instructions until the robot does the job; this first initiation is the last step of Djibouti's Grade 6 sequence, after Scratch.
**This lesson's own level:** It stands on the idea of an algorithm and a first Scratch script — instructions in order that a machine follows exactly — and on nothing else; what a robot is and how its programming differs from a screen program are built inside the lesson.

A lesson plan also says **what goes on top of the lesson**: at the exact places marked below, the lesson page carries an add-on — an image, a GIF, a video, an audio. Every slot is written as **"a picture of …" in words, plus one little line saying what the student does with it**. The words carry the picture while the course is built and while the AI learns from the books; on the website the real add-on is dropped into that slot and the little explanation stays as the student's guide. GIFs come first where a thing must be shown moving — a GIF here is 1–2 seconds.

## Sub lessons
The parts of this lesson, in order — the list the learner sees from the start, locked ahead, each opening when the one before it is proved:

1. **What a robot is, and what programming one means** — A robot is a machine that senses, decides from its program and acts — it moves or works in the real world; programming it means writing the exact ordered instructions it will follow, knowing it will do exactly what the instructions say, never what you meant.
2. **A first program for a robot — run, watch, fix** — Plan a small job as steps in order, give the robot those steps, run it and watch what it really does, then change one thing in the instructions and run it again — the run-watch-fix circle is how every robot program is finished.

Gate pool: all questions of the sub lesson — no hardness ranking is written in questions/, so the sub lesson's whole question set is the gate pool.

## Before this lesson
- Recommended first: the Scratch lessons in Programming (a first Scratch script) and Computational Thinking, and Robotics — Machines That Do People's Tasks in this title. Recommended, never forced — a learner may land on this lesson directly, and it stands alone; the hands-on can be done by acting the robot with no robot kit at all.
- Djibouti's own way is kept: in Djibouti's Grade 6 book this initiation is Chapitre 12, the final chapter, coming after the Scratch chapter — first programs on a screen, then a first program that moves a machine.

## What the learner can do when it ends
1. Say what a robot is: a machine that senses, decides from its program and acts in the real world.
2. Say what programming a robot means, and why the instructions must be exact and in order.
3. Plan a small robot job as steps in order.
4. Use the run-watch-fix circle: run the program, watch what the robot really does, change one thing, run again.

## What you need
Paper and a pencil. If a school educational robot or kit is available, use it for the hands-on; if not, a classmate acting as the robot does the same work.

## The run of the lesson (in order)
1. **Do it first** — Close your eyes and give a partner these instructions: "walk to the door." Watch what happens when the instructions leave steps out. A robot is stricter than a partner — it cannot guess the missing steps. This lesson is a first start at giving a machine instructions it can really follow. (lesson/lesson.md).
2. **The explanation** — the lesson text in lesson/lesson.md, in its parts in order.
   - ADD IMAGE: a picture of a small educational robot with its three parts labelled — sensors that sense, the program that decides, wheels and arms that act — the student names each part and the job it does.
   - ADD IMAGE: a picture of a short robot program as blocks or steps in order, with an arrow running from the written steps to the robot doing them — the student reads the steps aloud and says what the robot will do at each one.
   - ADD GIF: a GIF of a small robot following a line, stopping short, being reprogrammed and then reaching the end — the student says what changed between the two runs.
   - ADD AUDIO: a voice reading the lesson's key names and definitions aloud, in the order the lesson gives them — the student listens once through, then reads the same lines aloud along with the voice. (Audio is a described slot in this build; no audio file is made.)
3. **Say it to your companion** — the companion block in lesson/lesson.md.
   - ADD VIDEO: the script in video-script.md, filmed — the lesson in the super-simple voice (made later, when videos are made).
4. **Questions** — from questions/: multiple-choice, true-or-false, fill-in-the-blank, short-answer — served at the learner's level and teaching-mix (levels.md).
5. **Hands-on** — hands-on.md.

## If the learner is stuck
Expects the robot to understand the goal → a robot follows the instructions, not the goal; every step it needs must be written. The robot did something different from the plan → that difference is the lesson: watch what it really did, find the step that caused it, change that one thing and run again. No robot kit in the school → act it: one learner is the robot and follows only the written steps, exactly; the class sees the same run-watch-fix circle.
