# Code Review With a Checklist — true or false

Say true or false, and fix the false ones in your own words.

**1. (Sub lesson 1) True or false: Another programmer reads code before it is accepted, looking for faults, risks and unreadable places**
**Answer: True**

**2. (Sub lesson 1) True or false: Another programmer reads code before it is accepted, looking for faults, risks and unreadable places** — as the answer to: Why can't the writer review their own code as well?
**Answer: False — The writer reads what they meant, not what they wrote — the reviewer reads what is actually there**

**3. (Sub lesson 1) True or false: Faults, risks, and unreadable places**
**Answer: True**

**4. (Sub lesson 1) True or false: Faults, risks, and unreadable places** — as the answer to: Where does Armenia teach code review?

**5. (Sub lesson 1) True or false: Readable code before it (Lesson 19–20 area) and program debugging after it (Lesson 22)**

**6. (Sub lesson 2) True or false: Readable code before it (Lesson 19–20 area) and program debugging after it (Lesson 22)** — as the answer to: Why use a checklist at all?
**Answer: False — It makes review complete instead of impressionistic — nothing depends on the reviewer's mood or memory**

**7. (Sub lesson 2) True or false: Correctness, readability, safety, and tests**
**Answer: True**

**8. (Sub lesson 2) True or false: Correctness, readability, safety, and tests** — as the answer to: What form is each checklist item?

**9. (Sub lesson 2) True or false: It is revised whenever a real fault escapes review — the miss becomes a new item**
