**The one thing this lesson teaches:** Work you do not save is work you lose: a Scratch project is saved into its own folder under a name that describes it — "Space", "Football" — so the project can be found, reopened and continued.

## Sub lessons
The parts of this lesson, in order — the list the learner sees from the start, locked ahead, each opening when the one before it is proved:

1. **Saving the project — in its own folder** — To **save** a Scratch project is to write it to a file on the computer. Projects are **kept in their own folder** — one home for all your Scratch work — so projects never scatter among pictures and documents. Save when the project is made, and save again as it grows: the saved file is the project's memory.
2. **A name that describes the project** — The saved project takes a **name that describes it** — the guide's examples are **"Space"** and **"Football"**: a name that says what the project is, so future-you can pick it from the folder without opening everything. A describing name plus its own folder is the whole system: find it fast, open it, continue it.

Gate pool: all questions of the sub lesson — no hardness ranking is written in questions/, so the sub lesson's whole question set is the gate pool.
