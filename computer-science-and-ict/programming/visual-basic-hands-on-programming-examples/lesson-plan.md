# Lesson plan — Visual Basic — Hands-on Programming Examples

**Course:** Computer Science and ICT · **Title:** Programming · **Lesson:** Visual Basic — Hands-on Programming Examples
**Place in the curriculum:** ICT expansion — Fiji (2026-11-14) — in the title Programming on the ICT course ladder (TITLES.md). Built new from Fiji's student books (Fiji Ministry of Education / Technology and Employment Skills Training (TEST) section, Suva), because no existing lesson in the course covers this thing as its own lesson.
**The one thing this lesson teaches:** Two — one after the controls, one after variables and data types.
**This lesson's own level:** It stands on the earlier lessons of its title and on the book's own order — it follows the book's lessons in sequence, so its neighbours in the book are its natural companions. It stands alone for a learner landing on it directly.

A lesson plan also says **what goes on top of the lesson**: at the exact places marked below, the lesson page carries an add-on — an image, a GIF, a video, an audio. Every slot is written as **"a picture of …" in words, plus one little line saying what the student does with it**. The words carry the picture while the course is built and while the AI learns from the books; on the website the real add-on is dropped into that slot and the little explanation stays as the student's guide. GIFs come first where a thing must be shown moving — a GIF here is 1–2 seconds.

## Sub lessons
The parts of this lesson, in order — the list the learner sees from the start, locked ahead, each opening when the one before it is proved:

1. **First build — a working window from the controls** — The first hands-on example (printed p. 88) gathers everything before it — the IDE, good-application habits and the wider controls — into **one small working application built step by step**: form laid out, controls placed and named, code written behind them, program run and corrected. Its lesson is the course's method: a Visual Basic program is *assembled* — surface first, behaviour behind it — and every part the chapters described separately is felt working as one thing.
2. **Second build — variables and data types at work** — The second example (printed p. 99) follows the variables chapter for a reason: it builds a program that **takes in values, stores them in variables of chosen types, works on them and shows the result** — the input–process–output shape inside a real window. Fiji's two builds frame the whole chapter: controls without data make posters; data without controls has no face. A learner who has done both builds has not only read the course — they have its two hands.

Gate pool: all questions of the sub lesson — no hardness ranking is written in questions/, so the sub lesson's whole question set is the gate pool.

2. **The explanation** — the lesson text in lesson/lesson.md, in its parts in order.
