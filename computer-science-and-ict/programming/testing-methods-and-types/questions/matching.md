# Testing Methods and Types — matching

Match each item on the left with the one it belongs to on the right.

**1. (Sub lesson 1) What does black-box testing see?** → **Inputs and outputs only — the code is unseen; it tests what the program does**

**2. (Sub lesson 1) What does white-box testing use?** → **The code itself — test cases are chosen to walk particular paths, branches and loops**

**3. (Sub lesson 1) What can black-box testing miss?** → **An untested inner path**

**4. (Sub lesson 1) What can white-box testing miss?** → **A requirement nobody coded — the code can be perfect and the program still wrong**

**5. (Sub lesson 1) Why use both methods?** → **They cover each other's blind spots**

**6. (Sub lesson 2) What does regression testing do?** → **It re-runs old tests after a change, to catch what the change broke**

**7. (Sub lesson 2) Which type checks speed and load?** → **Performance testing**

**8. (Sub lesson 2) Which type checks people can use the program?** → **Usability testing**

**9. (Sub lesson 2) Name two more types by aim.** → **Functional testing and security testing**

**10. (Sub lesson 2) Why is testing called a rhythm, not a final event?** → **Tests run during building, at joining, before release and after every repair**
