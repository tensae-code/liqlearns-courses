# Testing Methods and Types — true or false

Say true or false, and fix the false ones in your own words.

**1. (Sub lesson 1) True or false: Inputs and outputs only — the code is unseen; it tests what the program does**
**Answer: True**

**2. (Sub lesson 1) True or false: Inputs and outputs only — the code is unseen; it tests what the program does** — as the answer to: What does white-box testing use?
**Answer: False — The code itself — test cases are chosen to walk particular paths, branches and loops**

**3. (Sub lesson 1) True or false: An untested inner path**
**Answer: True**

**4. (Sub lesson 1) True or false: An untested inner path** — as the answer to: What can white-box testing miss?
**Answer: False — A requirement nobody coded — the code can be perfect and the program still wrong**

**5. (Sub lesson 1) True or false: They cover each other's blind spots**
**Answer: True**

**6. (Sub lesson 2) True or false: They cover each other's blind spots** — as the answer to: What does regression testing do?
**Answer: False — It re-runs old tests after a change, to catch what the change broke**

**7. (Sub lesson 2) True or false: Performance testing**
**Answer: True**

**8. (Sub lesson 2) True or false: Performance testing** — as the answer to: Which type checks people can use the program?
**Answer: False — Usability testing**

**9. (Sub lesson 2) True or false: Functional testing and security testing**
**Answer: True**

**10. (Sub lesson 2) True or false: Functional testing and security testing** — as the answer to: Why is testing called a rhythm, not a final event?
**Answer: False — Tests run during building, at joining, before release and after every repair**
