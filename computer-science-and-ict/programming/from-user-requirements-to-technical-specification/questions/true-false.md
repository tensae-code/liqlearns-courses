# From User Requirements to Technical Specification — true-false

Say whether each statement is true or false.

**1. (Sub lesson 1) True or false: the answer to "User requirements state what?" is: What the users need the system to do**
**Answer: True**

**2. (Sub lesson 1) True or false: the answer to "User requirements come from whom?" is: An exact written statement of what will be built**
**Answer: False** — The users or client

**3. (Sub lesson 1) True or false: the answer to "Translating requirements means what?" is: Turning needs into technical language**
**Answer: True**

**4. (Sub lesson 1) True or false: the answer to "What is a technical specification?" is: A measured limit — for example a set response time**
**Answer: False** — An exact written statement of what will be built

**5. (Sub lesson 1) True or false: the answer to "Who builds from the specification?" is: The programmers and builders**
**Answer: True**

**6. (Sub lesson 2) True or false: the answer to "A requirement like 'fast' becomes what in a specification?" is: A system that does not fit its users**
**Answer: False** — A measured limit — for example a set response time

**7. (Sub lesson 2) True or false: the answer to "Why must a specification be exact?" is: So builders and users agree what is made**
**Answer: True**

**8. (Sub lesson 2) True or false: the answer to "Missing requirements cause what?" is: Costs more — so translation is done first**
**Answer: False** — A system that does not fit its users

**9. (Sub lesson 2) True or false: the answer to "The specification is checked against what?" is: The user requirements**
**Answer: True**

**10. (Sub lesson 2) True or false: the answer to "Changing requirements after building does what?" is: The users or client**
**Answer: False** — Costs more — so translation is done first
