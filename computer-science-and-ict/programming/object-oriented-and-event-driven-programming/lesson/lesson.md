# Object-Oriented and Event-Driven Programming

## Do it first

Cuba's Grade 11 programming chapter climbs in one line: computational thinking, structured programming, then this lesson's pair — object-oriented and event-driven — because the LiveCode implementation that follows is built exactly that way.

## Sub lesson 1 — Objects — data and actions in one thing

An **object** is one thing of the program — a button, a pupil, a card — holding **properties**, the data that describes it (its name, its colour, its mark), and **methods**, the actions it can do (show itself, calculate, move). Object-oriented programming **models the problem as objects that work together**, each keeping its own data safe inside itself and offering its actions to the others. The same object idea, made once, can be used many times — a class of pupils is one design, many pupils.

## Sub lesson 2 — Events — the program answers what happens

An **event-driven** program does not run top to bottom and stop: it **waits**, and when an **event** happens — the user clicks a button, presses a key, a timer fires — it runs the **handler**, the code attached to that event, then waits again. The user, not the program, decides the order of happenings. Cuba teaches the pair together because its implementation tool, LiveCode, works exactly so: objects on a card, each with scripts that answer its events.
