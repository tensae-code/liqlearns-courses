# Algorithm Performance — Worst Case, Input Size and Run Time — matching

Match each item on the left with the one it belongs to on the right.

**1. (Sub lesson 1) What is performance measured against?** → **The input size — how much data the algorithm is given**

**2. (Sub lesson 1) What grows with input size?** → **The execution time**

**3. (Sub lesson 1) What is the honest measure?** → **The shape of growth — double the input and time doubles, or quadruples**

**4. (Sub lesson 1) What is not the measure?** → **One stopwatch reading on one machine**

**5. (Sub lesson 1) What Greek word names efficiency here?** → **Αποδοτικότητα**

**6. (Sub lesson 2) What is the worst case?** → **The allowed input that makes the algorithm work hardest**

**7. (Sub lesson 2) Why judge by it?** → **A promise that holds in the worst case holds always**

**8. (Sub lesson 2) Give a worst case for searching.** → **The name that stands last in the list**

**9. (Sub lesson 2) Give a worst case for sorting.** → **The list that arrives in reverse order**

**10. (Sub lesson 2) When can the judgement be written?** → **Before any machine is switched on**
