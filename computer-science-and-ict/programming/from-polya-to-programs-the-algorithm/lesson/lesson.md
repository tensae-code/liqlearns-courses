# From Polya to programs — the algorithm

## Do it first

Explain to a friend, out loud, exactly how to make tea — so exactly that they cannot go wrong. Every gap you leave, they will fall into. A computer falls into every gap. This lesson tightens Polya's plan step into the thing a computer needs: an algorithm.

## The computing four steps

Polya's steps are adjusted for computing: (1) understand the problem, (2) develop an algorithm, (3) write the program, (4) test the program. 'Make a plan' becomes 'develop an algorithm' — because a computer's plan must be exact enough for a machine to follow.

## What an algorithm is

An algorithm is a sequence of clearly defined steps describing a process — a finite set of unambiguous instructions with a clear start and end. In short: a precise sequence of instructions for solving a problem, in human-understandable format, useful for explaining a multistep task to another person or a machine. Finite: it ends. Unambiguous: every step means exactly one thing.

## Grade 10 depth — what an algorithm is, defined three ways

Grade 10 defines the algorithm from three sides at once. An algorithm is **a precise method of solving a problem** — **a sequence of unambiguous, step-by-step instructions**. It is also defined as **a set of rules for carrying out calculations** by hand or machine; as **a finite step-by-step procedure to achieve a required result**; and as **a sequence of computational steps transforming input into output**.

A **program** is what an algorithm becomes when **converted into code a computer can execute**. A well-written algorithm is **free of logic errors** and **easy to code in any high-level language** — algorithms are **language-independent plain instructions**, so the **same algorithm gives the same output in any language**.

The teaching analogy is the kitchen: cooking **doro wot** from a new recipe — **read the steps, execute them in sequence, and the dish comes out right**.
