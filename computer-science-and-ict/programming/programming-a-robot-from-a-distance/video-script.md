# Video script — Programming a Robot From a Distance — Bugs and Telegraphy

The super-simple voice, for the video that rides on top of the lesson (lesson-plan.md, add-on list). Made later, when videos are made; the script is the slot's written form until then.

---

The séance pairs **bug** with **telegraphy (télégraphie)**: commanding an automaton **from a distance**, by sent messages, as the telegraph once sent words by wire. Distance changes programming: no pointing, no “no, the other left!” mid-run — the whole intention must travel inside the message. Instructions written for a distant machine must be complete, unambiguous, and checkable on arrival: what did I send, what did it do, where do they differ?
A bug beside the machine is an annoyance; a bug at a distance is a **diagnosis problem**: the fault could be in the writing, the sending, the reading, or the machine. The séance teaches method: keep the sent program (the copy is evidence), change one thing per new message, and let each reply report position and facing. Programmers of real distant machines — probes, robots, servers — work exactly this way: the message log is the only eyes you have.
