# Lesson plan — Representing Information Through Coding

**Course:** Computer Science and ICT · **Title:** Programming · **Lesson:** Representing Information Through Coding
**Place in the curriculum:** ICT expansion — Germany (2026-11-14) — in the title Programming on the ICT course ladder (TITLES.md). Built new from Germany's *Informatik 5 (Bayern NTG)*, because no existing lesson covers this thing as its own lesson.
**The one thing this lesson teaches:** coding is choosing a rule that represents information in another form — a code assigns each piece of information a sign or pattern to stand for it — so it can be stored, sent or kept by a machine or a person, and read back without loss when the rule is known.
**This lesson's own level:** It opens Germany's second strand — coding and cryptography. It stands on everyday signs (traffic lights, jersey numbers, barcodes) and needs no other lesson first.

A lesson plan also says **what goes on top of the lesson**: at the exact places marked below, the lesson page carries an add-on — an image, a GIF, a video, an audio. Every slot is written as **"a picture of …" in words, plus one little line saying what the student does with it**. The words carry the picture while the course is built and while the AI learns from the books; on the website the real add-on is dropped into that slot and the little explanation stays as the student's guide. GIFs come first where a thing must be shown moving — a GIF here is 1–2 seconds.

## Sub lessons
The parts of this lesson, in order — the list the learner sees from the start, locked ahead, each opening when the one before it is proved:

1. **What a code is — representation by rule** — Information against its representation: a code is the assignment rule (each item ↔ its sign). Examples across channels — Morse, barcode/QR, jersey numbers, traffic lights; encoding and decoding as the two directions of the rule.
2. **What a good code must do** — Unambiguous (one sign, one meaning) and uniquely decodable (a stream of signs splits back in only one way); length against effort — short signs for frequent items (Morse's E is one dot); codes that detect damage (a check digit idea) named.

Gate pool: all questions of the sub lesson — no hardness ranking is written in questions/, so the sub lesson's whole question set is the gate pool.

## Before this lesson
- Recommended first: nothing in this course — everyday signs are enough to start. Recommended, never forced — a learner may land on this lesson directly, and it stands alone.

## What the learner can do when it ends
1. Say what a code is, and name the rule that makes a given representation a code.
2. Encode and decode a short message with a simple given code.
3. Judge a code against the job: say why it must be unambiguous and suited to its channel.

## What you need
Paper and a pencil. A phone torch or a torch app helps for the Morse practice in the hands-on — light is a channel too.

## If the learner is stuck
Calls any writing 'a code' → a code is the assignment rule itself: no shared rule, no code, only marks. Designs signs without asking about the channel → first the channel (beeps? light? print?), then the signs it can carry.
