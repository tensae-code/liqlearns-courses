# Lesson plan — The Program Development Life Cycle

**Course:** Computer Science and ICT · **Title:** Programming · **Lesson:** The Program Development Life Cycle
**Place in the curriculum:** Phantom repair — Kenya (2026-11-25) — in the title Programming on the ICT course ladder (TITLES.md). Built new from Kenya's *Log On Computer Studies Form 3* (student book), because no existing lesson covers this thing as its own lesson — the live tree was checked for the slug and for near matches before building.
**The one thing this lesson teaches:** Programs are built in a cycle of stages: recognise and define the problem, design the program (algorithm, pseudocode or flowchart), code it in a programming language, test and debug it, implement it for its users, and maintain it as needs change — and skipping the early stages is how programs end up solving the wrong problem perfectly.
**This lesson's own level:** It stands on the lessons named under "Before this lesson"; it stands alone for a learner landing on it directly.

A lesson plan also says **what goes on top of the lesson**: at the exact places marked below, the lesson page carries an add-on — an image, a GIF, a video, an audio. Every slot is written as **"a picture of …" in words, plus one little line saying what the student does with it**. The words carry the picture while the course is built and while the AI learns from the books; on the website the real add-on is dropped into that slot and the little explanation stays as the student's guide. GIFs come first where a thing must be shown moving — a GIF here is 1–2 seconds.

## Sub lessons
The parts of this lesson, in order — the list the learner sees from the start, locked ahead, each opening when the one before it is proved:

1. **Before the code — recognising, defining and designing** — Stage 1, problem recognition: noticing that a task needs a program at all. Stage 2, problem definition: stating exactly what the program must do — its inputs, outputs and limits — agreed with the people who will use it. Stage 3, program design: planning the solution as an algorithm, written as pseudocode or drawn as a flowchart, before any real language is touched.
2. **Code, test, implement, maintain** — Stage 4, coding: writing the design in a real programming language. Stage 5, testing and debugging: running the program on test data to expose errors (testing) and finding and fixing those errors (debugging) — syntax, logic and runtime errors. Stage 6, implementation: installing the program for its real users, with data converted and users trained. Stage 7, maintenance: correcting, improving and adapting the program as needs change — the longest stage of all.

Gate pool: all questions of the sub lesson — no hardness ranking is written in questions/, so the sub lesson's whole question set is the gate pool.

## What the learner can do when it ends
1. Name the stages of the program development life cycle in order.
2. Say what is produced at each stage (definition, design, code, test results, a working system, updates).
3. Explain the difference between testing and debugging.
4. Argue why problem definition comes before coding, using a concrete example.

## What you need
Paper and a pencil.
