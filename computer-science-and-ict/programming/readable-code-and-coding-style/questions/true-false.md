# Readable Code and Coding Style — true or false

Say true or false, and fix the false ones in your own words.

**1. (Sub lesson 1) True or false: Code a competent reader can follow — saying what each part does without detective work**
**Answer: True**

**2. (Sub lesson 1) True or false: Code a competent reader can follow — saying what each part does without detective work** — as the answer to: What are readability's two great tools?
**Answer: False — Names and layout**

**3. (Sub lesson 1) True or false: The name says what the variable holds — the reader need not hunt for its meaning**
**Answer: True**

**4. (Sub lesson 1) True or false: The name says what the variable holds — the reader need not hunt for its meaning** — as the answer to: What does consistent indentation show?
**Answer: False — The structure — what sits inside what**

**5. (Sub lesson 1) True or false: As a quality feature of programs (Lesson 19, in the quality-features theme) — not a matter of taste**
**Answer: True**

**6. (Sub lesson 2) True or false: As a quality feature of programs (Lesson 19, in the quality-features theme) — not a matter of taste** — as the answer to: What is a coding style?
**Answer: False — A team's agreed set of readability rules — naming, braces, line length, comments**

**7. (Sub lesson 2) True or false: Consistency — learn the rules once, read everything at speed**
**Answer: True**

**8. (Sub lesson 2) True or false: Consistency — learn the rules once, read everything at speed** — as the answer to: Is one style magically best?
**Answer: False — No — an agreed, kept style beats a 'better' style kept only sometimes**

**9. (Sub lesson 2) True or false: Code review, and automatic formatting tools (plus the team's agreement)**
**Answer: True**

**10. (Sub lesson 2) True or false: Code review, and automatic formatting tools (plus the team's agreement)** — as the answer to: What should stand out in consistently styled code?
**Answer: False — Differences that mean something — not accidental differences of shape**
