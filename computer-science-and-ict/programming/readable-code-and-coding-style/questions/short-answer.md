# Readable Code and Coding Style — short answer

Answer in a short sentence of your own.

**1. (Sub lesson 1) What is readable code?**
**Answer: Code a competent reader can follow — saying what each part does without detective work**

**2. (Sub lesson 1) What are readability's two great tools?**
**Answer: Names and layout**

**3. (Sub lesson 1) Why is total_marks better than tm?**
**Answer: The name says what the variable holds — the reader need not hunt for its meaning**

**4. (Sub lesson 1) What does consistent indentation show?**
**Answer: The structure — what sits inside what**

**5. (Sub lesson 1) How does Armenia's Grade 10 book treat readability?**
**Answer: As a quality feature of programs (Lesson 19, in the quality-features theme) — not a matter of taste**

**6. (Sub lesson 2) What is a coding style?**
**Answer: A team's agreed set of readability rules — naming, braces, line length, comments**

**7. (Sub lesson 2) What is a style's real value?**
**Answer: Consistency — learn the rules once, read everything at speed**

**8. (Sub lesson 2) Is one style magically best?**
**Answer: No — an agreed, kept style beats a 'better' style kept only sometimes**

**9. (Sub lesson 2) Name two things that keep a style.**
**Answer: Code review, and automatic formatting tools (plus the team's agreement)**

**10. (Sub lesson 2) What should stand out in consistently styled code?**
**Answer: Differences that mean something — not accidental differences of shape**
