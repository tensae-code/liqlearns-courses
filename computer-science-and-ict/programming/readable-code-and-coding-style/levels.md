# Readable Code and Coding Style — sub lessons and depth

This file is the lesson's depth record, expressed as its SUB LESSONS. Practice is tied to the learner's skill number. The questions live in the type files; this file is the by-sub-lesson view.

## Sub lesson 1 — What makes code readable — names and layout
Sub lesson 1 questions from the type files. Pass mark: Code a competent reader can follow — saying what each part does without detective work; Names and layout; The name says what the variable holds — the reader need not hunt for its meaning; The structure — what sits inside what; As a quality feature of programs (Lesson 19, in the quality-features theme) — not a matter of taste.

## Sub lesson 2 — Coding style — one way, kept everywhere
Sub lesson 2 questions from the type files. Pass mark: A team's agreed set of readability rules — naming, braces, line length, comments; Consistency — learn the rules once, read everything at speed; No — an agreed, kept style beats a 'better' style kept only sometimes; Code review, and automatic formatting tools (plus the team's agreement); Differences that mean something — not accidental differences of shape.
