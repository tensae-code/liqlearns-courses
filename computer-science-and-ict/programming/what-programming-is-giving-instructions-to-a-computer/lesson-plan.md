# Lesson plan — What Programming Is — Giving Instructions to a Computer

**Course:** Computer Science and ICT · **Title:** Programming · **Lesson:** What Programming Is — Giving Instructions to a Computer
**Place in the curriculum:** ICT expansion — Finland (2026-11-14) — in the title Programming on the ICT course ladder (TITLES.md). Built new from Finland's *Ensiaskeleet ohjelmointiin* (student book, Oppilaan kirja, Versio 2.0), because no existing lesson teaches this thing as its own lesson.
**The one thing this lesson teaches:** Programming is giving instructions to a computer — and the computer follows those instructions exactly, as they are given, in the words of the course's opening idea: a program is the set of instructions, the code, built from commands (blocks) joined into a script that tells a sprite what to do.
**This lesson's own level:** It stands on nothing but giving instructions in daily life — a recipe, directions to a friend — and builds every programming word inside the lesson from the book's baker story.

A lesson plan also says **what goes on top of the lesson**: at the exact places marked below, the lesson page carries an add-on — an image, a GIF, a video, an audio. Every slot is written as **"a picture of …" in words, plus one little line saying what the student does with it**. The words carry the picture while the course is built and while the AI learns from the books; on the website the real add-on is dropped into that slot and the little explanation stays as the student's guide. GIFs come first where a thing must be shown moving — a GIF here is 1–2 seconds.

## Sub lessons
The parts of this lesson, in order — the list the learner sees from the start, locked ahead, each opening when the one before it is proved:

1. **Programming is giving instructions — the baker story** — Say what programming is and explain why a computer follows instructions exactly.
2. **The words: program, code, command, script, sprite** — Use the words program, code, command/block, script and sprite correctly.

Gate pool: all questions of the sub lesson — no hardness ranking is written in questions/, so the sub lesson's whole question set is the gate pool.

## Before this lesson
- Recommended first: nothing needs to come before it — this is the opening programming lesson of Finland's path. Recommended, never forced — a learner may land on this lesson directly, and it stands alone.
- Finland's own way is kept: this placement sits in Finland's two-part Scratch path — Part 1 moves towards the interactive-story project and Part 2 towards the self-built maze game, in the Luetaan (Let's read) then Ohjelmoidaan (Let's program) rhythm, with pair work, reflection and peer showing built in.

## What the learner can do when it ends
1. Say what programming is, in your own words.
2. Explain the baker story: why a computer does exactly what the instructions say, nothing more.
3. Use the words program, code, command/block, script and sprite correctly about one Scratch example.

## What you need
Paper and a pencil. No computer is needed to learn the idea; a computer with Scratch helps for the examples.

## The run of the lesson (in order)
1. **Do it first** — Tell a friend how to make a sandwich, step by step, while they do ONLY what you say — no more, no less. If a step is missing or unclear, the sandwich goes wrong. Keep that feeling — a computer is a listener like that, only stricter. (lesson/lesson.md).
2. **The explanation** — the lesson text in lesson/lesson.md, in its parts in order.
   - ADD IMAGE: a picture of the baker following a recipe step by step, with a computer beside the baker following its instructions in the same exact way — the student studies the picture and says, for each part of it, which part of the lesson it shows.
   - ADD IMAGE: a picture of five labelled cards — program, code, command/block, script, sprite — around a Scratch cat with a short stack of blocks beside it — the student studies the picture and says, for each part of it, which part of the lesson it shows.
   - ADD AUDIO: a voice reading the lesson's key names and definitions aloud, in the order the lesson gives them — the student listens once through, then reads the same lines aloud along with the voice. (Audio is a described slot in this build; no audio file is made.)

## If the learner is stuck
Thinks the computer understands what you mean → return to the baker: the story baker does only what the recipe says. Mixes up script and sprite → the sprite is WHO acts; the script is WHAT it is told to do.
