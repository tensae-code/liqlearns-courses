## Sub lessons
The parts of this lesson, in order — the list the learner sees from the start, locked ahead, each opening when the one before it is proved:

1. **Defining and calling — write once, use by name** — A **function** is a **named block of code that does one job**, written with **def**, a name, and the **parameters** it needs in brackets. Defining it only **teaches** the program the job; **calling** the function — writing its name with **arguments** — is what makes the job happen, as many times and in as many places as the program needs. The fruit of the pattern is the programmer's daily bread: write once, fix once, and a program that reads as a plan instead of a pile.
2. **Returning — the function hands back its answer** — A function may **return** a value: the job's result, handed back to the caller and usable in the caller's next step — assigned, printed, tested. Parameters carry values **in**; return carries the answer **out**; a function with neither is a pure doing (it prints, it draws), and one with both is the general shape. Kuwait's order — lists, tuples, dictionaries, then functions — is the course completing the first programmer's kit: hold data in structures, and hold work in functions.
