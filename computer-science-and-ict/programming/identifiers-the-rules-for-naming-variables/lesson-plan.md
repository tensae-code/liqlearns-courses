# Lesson plan - Identifiers - the rules for naming variables

**Course:** Computer Science and ICT · **Title:** Programming · **Lesson:** Identifiers - the rules for naming variables
**Place in the curriculum:** Unit 6 - Fundamentals of Programming (CURRICULUM.md).
**The one thing this lesson teaches:** a variable's name is an identifier: it must start with a letter or underscore, continue with letters, numbers or underscores only, not be a keyword, and respect case - and self-descriptive names keep programs understandable.

## Sub lessons
The parts of this lesson, in order - the list the learner sees from the start, locked ahead, each opening when the one before it is proved (the gate: README, "Units, Lessons and Sub Lessons (ruled 2026-11-08)"):

1. **The naming rules - first character, later characters** - An identifier is valid only if its first character is a letter or underscore, and any later characters are letters, numbers or underscores.
2. **Keywords and case** - An identifier must not be one of Python's keywords - the reserved words with predefined meanings - and it must respect case, since x and X are different identifiers.
3. **Valid or invalid - and choosing good names** - The worked failures: a name starting with a digit, one starting with *, a keyword used as a name, and one ending in & all fail; the style rule is to choose self-descriptive names so programs stay understandable.

Gate pool: all questions of the sub lesson - no hardness ranking is written in questions/, so the sub lesson's whole question set is the gate pool.

## What the learner can do when it ends
1. State the four naming rules.
2. Judge a name valid or invalid and name the rule it breaks.
3. Say what keywords are and why they cannot be used as names.
4. Explain why x and X are different identifiers, and why self-descriptive names are the style rule.

## If the learner is stuck
- Allows a digit inside a name but also at the start -> digits are welcome only AFTER the first character; the first must be a letter or underscore.
- Uses a keyword as a name -> keywords are reserved with predefined meanings; the language keeps them for itself.
