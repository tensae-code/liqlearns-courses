**The one thing this lesson teaches:** A variable can drive a robot: set a speed variable once and the virtual robot's movement blocks use it everywhere — change the one value and the whole drive changes — while the Monitor console lets you watch the variable's value as the program runs.

## Sub lessons
The parts of this lesson, in order — the list the learner sees from the start, locked ahead, each opening when the one before it is proved:

1. **A speed variable drives the robot** — In VEXcode VR, the robot's movement blocks can take their **speed from a variable** instead of a number typed into each block. Set the **speed variable** once — before the drive — and every movement that reads it obeys it. To change the robot's pace everywhere, you now change **one value in one place**.
2. **Watching values in the Monitor console** — The **Monitor console** shows the program's variables **while it runs**: watch the speed variable's **value change** as blocks assign and use it. The Monitor turns an invisible thing visible — when the robot misbehaves, the watched values tell you whether the variable held what you thought it held.

Gate pool: all questions of the sub lesson — no hardness ranking is written in questions/, so the sub lesson's whole question set is the gate pool.
