## Sub lessons
The parts of this lesson, in order — the list the learner sees from the start, locked ahead, each opening when the one before it is proved:

1. **From a route to a strategy** — A **route** solves one burrow; a **strategy** is an algorithm that solves the family: given any burrow layout, the strategy's rules produce the route, counting and saving movements (déplacements) as it goes. Séance 2's question — ‘can we find another algorithm that economises the number of movements?’ — moves pupils from drawing paths to designing the path-finder: rules like ‘always explore the nearest unvisited chamber first’ that pay off everywhere, not somewhere.
2. **Proving ‘always’** — A strategy that ‘works every time’ (qui fonctionne à tous les coups) makes a promise trials must test: run it on many burrows — easy, nasty, adversarial — count movements against the naive route, and hunt the burrow that breaks it. One breaking burrow refutes ‘always’ and improves the strategy; surviving every test the class can build earns provisional trust. This is the algorithmist's honesty standard, first met over a marmot: claims are sized to the tests survived.

Gate pool: all questions of the sub lesson — no hardness ranking is written in questions/, so the sub lesson's whole question set is the gate pool.

## The run of the lesson (in order)
1. **Do it first** — Your marmot route worked — once, on that burrow, with luck. The activity asks the colder question: can you find a route-plan that economises movements **every** time, on **every** burrow? Before reading on, say what changes when ‘worked once’ becomes ‘must always work’. (lesson/lesson.md).
