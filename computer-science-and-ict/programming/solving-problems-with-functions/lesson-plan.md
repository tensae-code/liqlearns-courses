# Lesson plan — Solving Problems with Functions

**Course:** Computer Science and ICT · **Title:** Programming · **Lesson:** Solving Problems with Functions
**Place in the curriculum:** ICT expansion — North Macedonia (2026-11-14) — in the title Programming on the ICT course ladder (TITLES.md). Built new from North Macedonia's *Informatics* (2026), because no existing lesson in the course covers this thing as its own lesson.
**The one thing this lesson teaches:** Real problems are solved by splitting them: each sub-job becomes a function with clear inputs and one output, the main program calls the functions in order and combines their results — so a word problem is first planned as a list of functions, then each function is written and tested on its own.
**This lesson's own level:** It stands on the earlier lessons of its title and on the North Macedonia book's own order — it follows the book's sections in sequence, so its neighbours in the book are its natural companions. It stands alone for a learner landing on it directly.

A lesson plan also says **what goes on top of the lesson**: at the exact places marked below, the lesson page carries an add-on — an image, a GIF, a video, an audio. Every slot is written as **"a picture of …" in words, plus one little line saying what the student does with it**. The words carry the picture while the course is built and while the AI learns from the books; on the website the real add-on is dropped into that slot and the little explanation stays as the student's guide. ## Sub lessons
The parts of this lesson, in order — the list the learner sees from the start, locked ahead, each opening when the one before it is proved:

1. **From word problem to function list** — Start from the **problem text**: underline what is **given** (the future arguments) and what is **asked** (the future return values). Each natural sub-job — read the data, compute a part, check a condition, print the result — becomes **one function**. The plan is a list: function names with their inputs and outputs, before any body is written.
2. **Write, test, combine — and practise** — Each function is written and **tested alone** with values whose answers are known by hand; only then are they **combined**, with main calling them in the planned order. The book follows this with a dedicated **exercises** set (§ Theme 2, exercises on functions): the drill is always the same round — plan the split, test the parts, assemble, and check the whole against a hand-worked example.

Gate pool: all questions of the sub lesson — no hardness ranking is written in questions/, so the sub lesson's whole question set is the gate pool.
