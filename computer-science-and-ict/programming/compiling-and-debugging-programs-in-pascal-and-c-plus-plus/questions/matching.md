# Compiling and Debugging Programs in Pascal and C++ — matching

Match each item on the left with the one it belongs to on the right.

**1. (Sub lesson 1) What does compilation do?** → **It translates the whole program text into machine language before any of it runs**

**2. (Sub lesson 1) What does a syntax error do?** → **It stops compilation — the compiler lists errors by line**

**3. (Sub lesson 1) What does linking add?** → **The libraries' ready pieces, joined into one executable file**

**4. (Sub lesson 1) What does a clean compile prove?** → **That the text is legal — not yet that the program is right**

**5. (Sub lesson 1) How does the compiler report?** → **By line, in terse messages the annexes teach to read**

**6. (Sub lesson 2) Which errors survive compilation?** → **Runtime errors (division by zero, endless loops) and logic errors (wrong answers)**

**7. (Sub lesson 2) State debugging's method in order.** → **Reproduce small, watch the values, locate the first wrong moment, fix, test again**

**8. (Sub lesson 2) What is a breakpoint?** → **A chosen line where the run pauses so the state can be inspected**

**9. (Sub lesson 2) What two ways of watching values are named?** → **Inserted print statements, and the debugger's stepping with breakpoints**

**10. (Sub lesson 2) What is the annexes' stance on debugging?** → **It is half the craft — practised by method, not by staring**
