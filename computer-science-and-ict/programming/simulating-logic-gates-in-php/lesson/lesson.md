# Simulating Logic Gates in PHP

## Do it first

The enrichment telling of Egypt's Grade 12 project: after each gate is simulated in VB.NET, the same simulation is produced in PHP — the gate as a web page, its inputs a form, its output a page the server builds. The book marks these PHP versions enrichment: the logic is the same, the medium is the stretch.

## Sub lesson 1 — The gate as a web page — form in, page out

The PHP simulation rebuilds the VB.NET project's anatomy in web parts. The **inputs** are a **form** — the visitor chooses the input values and submits; the **server** runs the PHP, which reads the submitted values, applies the **gate's logic**, and **generates the output page** showing the result — the lamp now a drawn or written state in the returned HTML. The round trip is the difference that teaches: the VB.NET program reacts instantly on one machine, while the PHP simulation sends the inputs away and waits for a rebuilt page — the dynamic-page rhythm of the Grade 11 course, now carrying Grade 12's logic.

## Sub lesson 2 — Same gates, second language — why build it twice

Egypt's double build — every gate in VB.NET, then again in PHP — is a deliberate argument about what programming **is**. The truth tables do not change; the AND that demands both inputs in a desktop form demands both in a web page. What changes is everything around the logic: controls become form fields, instant reaction becomes request and response, the lamp becomes generated HTML. A pupil who has carried the same logic across that change has learned the transferable thing — the gate — separately from the perishable thing — this year's tool. The PHP subjects are marked **enrichment** because the argument is completed by the VB.NET builds; the PHP builds are for those ready to watch the logic survive a change of world.
