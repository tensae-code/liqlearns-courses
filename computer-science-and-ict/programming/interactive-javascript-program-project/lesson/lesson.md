# Interactive JavaScript Program — Project

## Do it first

The chapter's pieces — types, control, library, functions, arrays — meet in one build. Malaysia's JavaScript chapter closes with an interactive program project. In this lesson you build a page program that takes a user's input and answers it, whole.

## Sub lesson 1 — The brief — a program that answers

The project program is **interactive**: it **takes input** from its user (typed values, choices, clicks), **processes** it with the chapter's structures, and **answers** on the page — a quiz that marks itself, a converter that converts, a marks tool that bands and totals. The brief is fixed before coding: the user, the inputs, the processing, the answers — because an interactive program is a **conversation**, and a conversation is designed from both sides, not discovered by typing code.

## Sub lesson 2 — Building with the whole chapter

The build **combines**: variables and constants hold the state; **if…else** judges the answers; **loops over arrays** carry the lists (questions, marks, items); **functions** each do one job (ask, check, report); the **standard library** is called for what it already does. The program is tested as a conversation — right answers, wrong answers, empty answers, answers at the edges — because a user will send all of them. Malaysia's project standard is the chapter in one artefact: if any structure from the chapter is missing, the brief usually shows where it belonged.
