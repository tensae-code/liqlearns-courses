# Programming Applications for Mobile Devices

## Do it first

The computer in every pocket runs programs written on purpose for it. Grade 10's applications unit opens that workshop: what makes a mobile application different from the programs of the desktop chapters before it.

## Sub lesson 1 — The mobile difference — small screen, touch, sensors, events

A mobile application is written for a device that is **carried**: a **small touch screen** instead of mouse and wide monitor, **sensors** (position, movement, camera, microphone) as its senses, and a life of **interruptions** — calls, messages, a battery ending. So mobile programming is **event-driven** from birth: the application waits, the user touches, the sensor reports, the system interrupts, and the program must answer each gracefully and keep its state through all of them.

## Sub lesson 2 — Making and delivering a mobile application

The chapter follows an application from **idea to the device's store**: designed for its screen and its user's one-handed moments, built in the **mobile programming environments** the book introduces (block and text homes where the application is assembled and tried on emulated and real devices), and delivered through the **application store**, which is how mobile software reaches its users and its updates reach back. Greece teaches the route in Grade 10's applications course so the phone's programs stop being weather — things that simply happen — and become artefacts with makers, tools and a road to the hand.
