## Sub lessons
The parts of this lesson, in order — the list the learner sees from the start, locked ahead, each opening when the one before it is proved:

1. **The mobile difference — small screen, touch, sensors, events** — A mobile application is written for a device that is **carried**: a **small touch screen** instead of mouse and wide monitor, **sensors** (position, movement, camera, microphone) as its senses, and a life of **interruptions** — calls, messages, a battery ending. So mobile programming is **event-driven** from birth: the application waits, the user touches, the sensor reports, the system interrupts, and the program must answer each gracefully and keep its state through all of them.
2. **Making and delivering a mobile application** — The chapter follows an application from **idea to the device's store**: designed for its screen and its user's one-handed moments, built in the **mobile programming environments** the book introduces (block and text homes where the application is assembled and tried on emulated and real devices), and delivered through the **application store**, which is how mobile software reaches its users and its updates reach back. Greece teaches the route in Grade 10's applications course so the phone's programs stop being weather — things that simply happen — and become artefacts with makers, tools and a road to the hand.

## The run of the lesson (in order)
1. **Do it first** — The computer in every pocket runs programs written on purpose for it. Grade 10's applications unit opens that workshop: what makes a mobile application different from the programs of the desktop chapters before it. (lesson/lesson.md).
2. **The explanation** — the lesson text in lesson/lesson.md, in its parts in order.
   - ADD IMAGE: a picture of the mobile difference — small screen, touch, sensors, events as the lesson describes it — the student studies the picture and names what each part shows.
   - ADD GIF: a GIF of making and delivering a mobile application in action — the student watches once, then says what changed and why.
   - ADD AUDIO: a voice reading the lesson's key names and definitions aloud, in the order the lesson gives them — the student listens once through, then reads the same lines aloud along with the voice. (Audio is a described slot in this build; no audio file is made.)

4. **Questions** — from questions/: multiple-choice, true-false, matching, short-answer — served at the learner's level and teaching-mix (levels.md).
5. **Hands-on** — hands-on.md.
