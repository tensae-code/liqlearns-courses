# Writing Good Visual Basic Applications — true-false

Say whether each statement is true or false.

**1. (Sub lesson 1) True or false: the answer to "Who are a good application's two judges?" is: Its user, and the next programmer who reads its code**
**Answer: True**

**2. (Sub lesson 1) True or false: the answer to "What does clear mean at the surface?" is: Buttons do what their labels promise, in the places users expect**
**Answer: False** — Every control labelled so its job is plain

**3. (Sub lesson 1) True or false: the answer to "What does predictable mean?" is: Buttons do what their labels promise, in the places users expect**
**Answer: True**

**4. (Sub lesson 1) True or false: the answer to "What does kind mean?" is: The user's — not the programmer's pride**
**Answer: False** — It asks only for what it needs, warns before anything is lost, and reports in the user's words

**5. (Sub lesson 1) True or false: the answer to "Whose experience is Fiji's standard?" is: The user's — not the programmer's pride**
**Answer: True**

**6. (Sub lesson 2) True or false: the answer to "What names must good code carry?" is: Where a choice needs explaining**
**Answer: False** — Meaningful names for controls and variables

**7. (Sub lesson 2) True or false: the answer to "Where do comments belong?" is: Where a choice needs explaining**
**Answer: True**

**8. (Sub lesson 2) True or false: the answer to "What layout does good code keep?" is: A fault can be found in the part that does that job**
**Answer: False** — Orderly — one job per procedure

**9. (Sub lesson 2) True or false: the answer to "Why does good layout help with faults?" is: A fault can be found in the part that does that job**
**Answer: True**

**10. (Sub lesson 2) True or false: the answer to "When is goodness applied?" is: Its user, and the next programmer who reads its code**
**Answer: False** — As a habit from the first form — not a finish applied at the end
