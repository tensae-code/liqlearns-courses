# Scientific Programming — Solving Equations Algorithmically

## Do it first

Grade 9's final unit turns the year's programming onto the school subject beside it: mathematics. An equation stops being only a puzzle for the hand and becomes a problem a program can settle — if the algorithm is honest about what 'solve' means.

## Sub lesson 1 — Solving by algorithm — steps a machine can repeat

To solve an equation **algorithmically** is to write **exact, repeatable steps** that take the equation's givens to its roots: for the quadratic, the discriminant's test and the formula's arithmetic, written once and run for any coefficients. The program's virtues are the mathematician's: it **tests before it divides** (is the leading coefficient zero? is the discriminant negative — and what is the honest answer then?), so every case the hand-solver is taught to fear becomes a branch the program must name.

## Sub lesson 2 — Iteration and approximation — answers good enough, proved

Not every equation surrenders to a formula: the unit's second craft is **iteration** — start from a **guess**, improve it by a rule, and stop when the improvement is **smaller than the tolerance the job sets**, so the answer is an **approximation with a known honesty**, not a pretended exactness. Scientific programming is named for this union: mathematics supplies the methods, programming supplies the tireless repetition, and the learner supplies the judgement of when 'close enough, proved' beats 'exact, never'.
