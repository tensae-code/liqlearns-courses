# Handling Runtime Errors — matching

Match each item on the left with the one it belongs to on the right.

**1. (Sub lesson 1) What is a runtime error?** → **A fault that appears while the program executes, when the data breaks an operation**

**2. (Sub lesson 1) Name two runtime errors.** → **Division by zero; a file that is not there (also root of a negative, value too large for its type)**

**3. (Sub lesson 1) How does it differ from a syntax error?** → **Syntax is caught by the translator before the run; runtime appears in the run**

**4. (Sub lesson 1) How does it differ from a logic error?** → **A logic error runs quietly to a wrong answer; a runtime error stops the run**

**5. (Sub lesson 1) What is the stop called?** → **Abnormal termination**

**6. (Sub lesson 2) What does handling mean?** → **Building the program's answer before the blow lands — check the dangerous data first**

**7. (Sub lesson 2) Name the three checks.** → **Divisor not zero; file exists; value in range**

**8. (Sub lesson 2) What roads may the program take when a check fails?** → **A message naming the trouble, a fresh chance to input, a safe ending**

**9. (Sub lesson 2) What is the chapter's design rule?** → **Every operation that can break on data must be met by its check**
