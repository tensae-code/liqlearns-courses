## Sub lessons
The parts of this lesson, in order — the list the learner sees from the start, locked ahead, each opening when the one before it is proved:

1. **The task — a robot that helps me** — The project asks each pupil to **design a robot that helps them**: name the help needed — a real task in the pupil's own day — and design the robot for exactly that help. The robot is a design, not a purchase: what it must sense, what it must do, and how the pupil would know it had helped. Choosing the help is the thinking; a robot designed for everyone helps no one in particular.
2. **Designing with the four stages** — The design is worked in the unit's craft: set the **goal** (the help, in one sentence), the **smart plan** (the steps the robot follows), its **flowchart**, and then the **code instructions** the robot would run — the same four stages the Little Programmer lessons taught, now spent on the pupil's own invention. The project is the unit's proof: the stages are a way of working, not a page in the book.

Gate pool: all questions of the sub lesson — no hardness ranking is written in questions/, so the sub lesson's whole question set is the gate pool.
