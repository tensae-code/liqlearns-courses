# Breakpoints and stepping — hunting a TypeError — multiple choice

Pick the one right answer.

**1. (Sub lesson 1)** Go advances execution until —
a) the program ends only  b) a breakpoint or an input request  c) ten lines pass
**Answer: b) b) a breakpoint or an input request**

**2. (Sub lesson 1)** Step —
a) closes the debugger  b) shows the current line's internal commands and moves to the next  c) deletes a breakpoint
**Answer: b) b) shows the current line's internal commands and moves to the next**

**3. (Sub lesson 1)** In Debug Control you can inspect —
a) variables' values as code executes  b) other students' files  c) the internet
**Answer: a) a) variables' values as code executes**

**4. (Sub lesson 2)** A breakpoint line highlights —
a) red  b) yellow  c) blue
**Answer: b) b) yellow**

**5. (Sub lesson 2)** A breakpoint is removed by —
a) right-click → Clear Breakpoint  b) Alt+3  c) closing IDLE only
**Answer: a) a) right-click → Clear Breakpoint**

**6. (Sub lesson 2)** The TypeError in the traced example is fixed by —
a) deleting the input line  b) casting the input to integer  c) adding a comment
**Answer: b) b) casting the input to integer** — Keyboard input is text; int() casts it to a number.
