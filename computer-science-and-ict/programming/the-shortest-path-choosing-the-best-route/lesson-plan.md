# Lesson plan — The Shortest Path — Choosing the Best Route

**Course:** Computer Science and ICT · **Title:** Programming · **Lesson:** The Shortest Path — Choosing the Best Route
**Place in the curriculum:** ICT expansion — Azerbaijan (2026-11-14) — in the title Programming on the ICT course ladder (TITLES.md). Built new from Azerbaijan's *İnformatika 2, Grade 2*, because no existing lesson teaches this thing as its own lesson at this level.
**The one thing this lesson teaches:** When several routes lead to the same place, the shortest path is the route with the least travelling — choosing it means comparing the routes and picking the best one.
**This lesson's own level:** Grade 2 simple — it stands on the child's own everyday world and on the lessons named below; every new word is built inside the lesson from things the child can do at once.

## Before this lesson
- Recommended first: Following an Algorithm Step by Step in Programming. Recommended, never forced — a learner may land on this lesson directly, and it stands alone. It is kept separate from Dijkstra's Algorithm — the Shortest Path: that lesson is for older learners and works with weighted graphs; this one is Grade 2 route-choosing in everyday places.

## What the learner can do when it ends
1. Say what a path and the shortest path are.
2. Compare two or three routes between the same start and finish and choose the shortest.
3. Say why the comparison must use the same start and the same finish for every route.

## What you need
A simple drawn map of familiar routes, or the real routes of the school grounds. No computer is needed.

## The run of the lesson (in order)

## If the learner is stuck
Chooses by which route looks nicest → return to the measure: fewest steps / least travelling wins in this lesson. Compares routes to different finishes → fix the finish first: same start, same finish, then compare.
