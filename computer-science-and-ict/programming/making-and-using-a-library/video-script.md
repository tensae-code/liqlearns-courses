# Video script — Making and Using a Library

The super-simple voice, for the video that rides on top of the lesson (lesson-plan.md, add-on list). Made later, when videos are made; the script is the slot's written form until then.

---

A **library** is a collection of ready procedures and functions, packaged under one name so any program can **call** them without rewriting them. Indonesia's Grade 9 book teaches **developing** a library inside visual programming: in Scratch and Blockly, your own blocks — procedures you defined for one project — can be gathered, named and kept, so the next project starts standing on this one's work. The library is modularisation with an address: not just 'a part of this program', but a shelf other programs visit.
Grade 12 meets the same idea from the user's side: Arduino ships with **libraries** for its common parts — a library to run the servo, one to write the LCD — and the IDE's **Library Manager** installs more, while **Include Library** adds one to a sketch, after which its functions are called like the language's own. The two lessons are one truth from two ends: every library in use was once made by someone who packaged their work well — named clearly, documented honestly, and built to be called by strangers.
