# Program Quality and Testing — matching

Match each item on the left with the one it belongs to on the right.

**1. (Sub lesson 1) Name three quality features beyond 'it runs'.** → **Correctness, readability, reliability (also efficiency and usability)**

**2. (Sub lesson 1) What does correctness demand?** → **Right answers for all honest inputs — not just the ones tried**

**3. (Sub lesson 1) What does reliability add?** → **The program behaves under stress and bad input, not only in the easy case**

**4. (Sub lesson 1) Why is readability a quality feature?** → **Programs are read and fixed by people — code nobody can follow cannot be trusted or repaired**

**5. (Sub lesson 1) Across which Armenia grades does quality run?** → **Grade 6 (prerequisites), Grade 10 (quality features) and Grade 12 (testing as the proof)**

**6. (Sub lesson 2) What is a test case?** → **One chosen input with its expected result written down before running**

**7. (Sub lesson 2) Name the testing levels in order.** → **Unit (parts alone), integration (parts together), system (the whole program), acceptance (the user's check)**

**8. (Sub lesson 2) What can testing prove?** → **That faults are present — never that none remain**

**9. (Sub lesson 2) When is the expected result written?** → **Before running the test — otherwise the tester just accepts whatever comes out**

**10. (Sub lesson 2) Why is quality 'built in, not only tested in'?** → **Because testing cannot prove a program fault-free, quality must be made during building, with testing as the check**
