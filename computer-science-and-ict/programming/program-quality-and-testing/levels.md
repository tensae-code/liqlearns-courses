# Program Quality and Testing — sub lessons and depth

This file is the lesson's depth record, expressed as its SUB LESSONS. Practice is tied to the learner's skill number. The questions live in the type files; this file is the by-sub-lesson view.

## Sub lesson 1 — Program quality — the features a good program has
Sub lesson 1 questions from the type files. Pass mark: Correctness, readability, reliability (also efficiency and usability); Right answers for all honest inputs — not just the ones tried; The program behaves under stress and bad input, not only in the easy case; Programs are read and fixed by people — code nobody can follow cannot be trusted or repaired; Grade 6 (prerequisites), Grade 10 (quality features) and Grade 12 (testing as the proof).

## Sub lesson 2 — Testing — the proof: stages, levels and the test case
Sub lesson 2 questions from the type files. Pass mark: One chosen input with its expected result written down before running; Unit (parts alone), integration (parts together), system (the whole program), acceptance (the user's check); That faults are present — never that none remain; Before running the test — otherwise the tester just accepts whatever comes out; Because testing cannot prove a program fault-free, quality must be made during building, with testing as the check.
