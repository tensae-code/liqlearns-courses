# Video script — Program Quality and Testing

The super-simple voice, for the video that rides on top of the lesson (lesson-plan.md, add-on list). Made later, when videos are made; the script is the slot's written form until then.

---

A program's **quality** is judged by features beyond 'it runs': **correctness** (right answers for all honest inputs), **readability** (others can follow the code), **reliability** (it behaves under stress and bad input), **efficiency** (it uses time and memory reasonably), and **usability** (people can actually use it). Armenia returns to quality across the years: prerequisites for ensuring quality in Grade 6 (§20), the quality features theme in Grade 10, and testing as the proof in Grade 12.
**Testing** is running the program with chosen inputs to expose faults. A **test case** is one chosen input with its expected result written down *before* running. Testing works in **stages/levels**: parts alone (unit level), parts together (integration level), the whole program (system level), and the user's own check (acceptance level). Testing can show faults are present; it can never prove none remain — which is why quality is built in, not only tested in.
