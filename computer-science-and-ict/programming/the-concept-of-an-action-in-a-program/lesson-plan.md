## Sub lessons
The parts of this lesson, in order — the list the learner sees from the start, locked ahead, each opening when the one before it is proved:

1. **An action — the program's smallest deed** — An **action** is one **elementary operation performed by the executor** while a program runs: taking a value, computing, storing, showing, choosing. Actions differ from the program's *text*: the text stands still on the page, while actions **happen in time, one after another**, changing the program's state — the values in memory — as they go. To understand any program is to follow its actions: what happens first, what changes, what happens next. A program whose actions you cannot trace is a program you do not yet understand.
2. **Elementary and composed actions** — Some actions are **elementary** for their executor — one command, done at once, like adding two numbers in a register. Others are **composed**: named blocks (an instruction, a procedure) that unfold into many elementary actions when executed. The same deed can be elementary on one level and composed on another: 'print the table' is one action to the caller, a hundred to the machine. Programming is largely the art of **composing**: building big actions from small ones until the program reads as a few clear deeds.
