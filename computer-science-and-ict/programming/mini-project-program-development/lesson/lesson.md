# Mini Project — Program Development

## Do it first

Malaysia's Grade 9 book closes its opening chapter with a test of the whole method: one small real problem, carried from first understanding to a working program, with the thinking reported at every phase. In this lesson you run that mini project — small in size, complete in shape.

## Sub lesson 1 — The brief and the phases

The **mini project** takes a **situasi** — a small problem situation from school or home life (a club's attendance, a canteen queue, a library's loans) — and carries it through the **phases of program development**: problem analysis, algorithm design, coding, testing, and documentation. The project's rule is completeness over size: the problem is deliberately small so that **no phase is skipped** — a skipped phase is the fault the project exists to expose.

## Sub lesson 2 — Reporting the thinking, phase by phase

At each phase the developer **reports** which computational-thinking technique did the work: decomposition in the analysis (the problem broken into its parts), pattern recognition and abstraction in the design (the repeated shape kept, the clutter dropped), sequencing in the algorithm, and checking in the testing. The finished project is handed over as the program **plus** its report — Malaysia's point is that the report is not decoration: it is the evidence that the program was developed, not merely typed.
