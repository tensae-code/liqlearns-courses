# Lesson plan — Mini Project — Program Development

**Course:** Computer Science and ICT · **Title:** Programming · **Lesson:** Mini Project — Program Development
**Place in the curriculum:** ICT expansion — Malaysia (2026-11-14) — in the title Programming on the ICT course ladder (TITLES.md). Built new from Malaysia's student books (Kementerian Pendidikan Malaysia), because no existing lesson in the course covers this thing as its own lesson — the live tree and live lesson content were checked for the slug and for near matches before building.
**The one thing this lesson teaches:** A mini project that carries a small problem through every phase of program development — computational thinking reported phase by phase, as Malaysia's Tingkatan 3 book sets it
**This lesson's own level:** It stands on the earlier lessons of its title and on the book's own order — it follows the book's lessons in sequence, so its neighbours in the book are its natural companions. It stands alone for a learner landing on it directly.

A lesson plan also says **what goes on top of the lesson**: at the exact places marked below, the lesson page carries an add-on — an image, a GIF, a video, an audio. Every slot is written as **"a picture of …" in words, plus one little line saying what the student does with it**. The words carry the picture while the course is built and while the AI learns from the books; on the website the real add-on is dropped into that slot and the little explanation stays as the student's guide. GIFs come first where a thing must be shown moving — a GIF here is 1–2 seconds.

## Sub lessons
The parts of this lesson, in order — the list the learner sees from the start, locked ahead, each opening when the one before it is proved:

1. **The brief and the phases** — The **mini project** takes a **situasi** — a small problem situation from school or home life (a club's attendance, a canteen queue, a library's loans) — and carries it through the **phases of program development**: problem analysis, algorithm design, coding, testing, and documentation. The project's rule is completeness over size: the problem is deliberately small so that **no phase is skipped** — a skipped phase is the fault the project exists to expose.
2. **Reporting the thinking, phase by phase** — At each phase the developer **reports** which computational-thinking technique did the work: decomposition in the analysis (the problem broken into its parts), pattern recognition and abstraction in the design (the repeated shape kept, the clutter dropped), sequencing in the algorithm, and checking in the testing. The finished project is handed over as the program **plus** its report — Malaysia's point is that the report is not decoration: it is the evidence that the program was developed, not merely typed.

Gate pool: all questions of the sub lesson — no hardness ranking is written in questions/, so the sub lesson's whole question set is the gate pool.
