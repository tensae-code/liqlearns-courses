# Evaluating Expressions — and Operator Precedence in Pascal — true or false

Say true or false, and fix the false ones in your own words.

**1. (Sub lesson 1) True or false: Operands (values) joined by operators (operations)**
**Answer: True**

**2. (Sub lesson 1) True or false: Operands (values) joined by operators (operations)** — as the answer to: What does evaluating an expression mean?
**Answer: False — Working it out to one value**

**3. (Sub lesson 1) True or false: Pascal expressions are written flat in one line — the line has no floors**
**Answer: True**

**4. (Sub lesson 1) True or false: Pascal expressions are written flat in one line — the line has no floors** — as the answer to: What is a standard function call inside an expression?
**Answer: False — An operand — evaluated to its value where it stands**

**5. (Sub lesson 1) True or false: +, −, *, / (also: div, mod)**
**Answer: True**

**6. (Sub lesson 2) True or false: +, −, *, / (also: div, mod)** — as the answer to: State the precedence order.
**Answer: False — Brackets first, then the multiplication family (*, /, div, mod), then the addition family (+, −), left to right within a level**

**7. (Sub lesson 2) True or false: 14 — multiplication binds before addition**
**Answer: True**

**8. (Sub lesson 2) True or false: 14 — multiplication binds before addition** — as the answer to: How do you make it 20?
**Answer: False — Bracket it: (2 + 3) * 4 — brackets outrank all**

**9. (Sub lesson 2) True or false: Weakest of all — they compare finished values**
**Answer: True**

**10. (Sub lesson 2) True or false: Weakest of all — they compare finished values** — as the answer to: What is the professional's rule?
**Answer: False — When the reader could hesitate, bracket — clarity is for people**
