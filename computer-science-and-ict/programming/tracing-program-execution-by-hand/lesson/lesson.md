# Tracing Program Execution by Hand

## Do it first

The teacher guide's worked solutions do by hand what the computer does silently: follow a variable through every turn of a loop, on paper, until the program's behaviour is fully seen. This lesson is that tracing craft at program level. (This lesson stands on teacher-guide evidence only.)

## Sub lesson 1 — Tracing variables through iterations

**Tracing** a program follows its execution line by line with real values: each assignment updates the traced value **in writing**, each condition is decided from the written values, and each **loop iteration** is a fresh line in the trace — the variable's whole biography, from its birth value to its final one. The guide's worked prime-number and task-manager programs are traced this way because a loop's effect is invisible in the code alone: the same line, worked ten times with ten different values, is the program.

## Sub lesson 2 — What tracing by hand is for

Hand tracing is the programmer's X-ray: it **predicts** a program's output before running, **finds** the iteration where a value first goes wrong, and **teaches** what the machine actually does against what the writer imagined. Its discipline is the tracker's: no step skipped, no value guessed — the trace is evidence, and a guessed value in it is a forged witness. Jordan's guide builds the craft into its solutions so teachers can show, not merely state, why a program answers as it does.
