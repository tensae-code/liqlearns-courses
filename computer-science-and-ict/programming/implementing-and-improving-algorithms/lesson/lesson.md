# Implementing and Improving Algorithms

## Do it first

An algorithm on paper is a promise. Implementing is keeping it; improving is keeping it better. This lesson learns both acts, in the algorithms unit's closing lesson.

## Sub lesson 1 — Implementing — from algorithm to working form

**Implementing** an algorithm is expressing it in a form that can be **executed** — a program in a language, a precise procedure a person or machine follows — **without changing its logic**. Implementation is tested against the algorithm: same inputs, same outputs, every step accounted for. The implementer's faults are translation faults — a condition flipped, a step dropped, a loop's end moved — and the tracking craft of the last lesson is how they are caught: track the implementation against the algorithm, row by row.

## Sub lesson 2 — Improving — same answer, better road

An algorithm is **improved** when it reaches the same answer with less: **fewer steps**, less memory, clearer working. Improvement begins by **counting** — how many steps for this size of problem, and how the count grows — then hunting the waste: steps repeated that could be remembered, searches that could stop early, work done for cases that cannot occur. Jordan's closing rule is the improver's honesty: an improvement must be **proved** — tracked and tested on the same cases — because a 'faster' algorithm that answers differently has not improved the road; it has changed the destination.
