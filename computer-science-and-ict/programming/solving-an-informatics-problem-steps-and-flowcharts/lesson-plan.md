## Sub lessons
The parts of this lesson, in order — the list the learner sees from the start, locked ahead, each opening when the one before it is proved:

1. **The steps — from problem to tested algorithm** — An **informatics problem** is solved in order. **Understand the problem**: what is asked, what is given. **Name the input and the output**: the data the solution starts from and the result it must produce. **Plan and model it mathematically**: turn the situation into quantities and relations a machine can work. **Build the algorithm**: the step order that carries input to output. **Test it**: run it on known cases and compare — an untested algorithm is a hope, not a solution.
2. **Flowcharts and trace tables — drawing and proving the plan** — The algorithm is drawn as a **flowchart**: the book draws all three shapes of control — **sequence** (steps one after another), **branching** (a test choosing the road) and **loops** (steps repeated) — in the standard flowchart blocks. The test is recorded in a **trace table**: each step's effect on every quantity, row by row, so an error can be pointed at the exact row where the values went wrong. Mongolia's pairing is the lesson's heart: the flowchart is the plan made visible; the trace table is the plan made answerable.

Gate pool: all questions of the sub lesson — no hardness ranking is written in questions/, so the sub lesson's whole question set is the gate pool.
