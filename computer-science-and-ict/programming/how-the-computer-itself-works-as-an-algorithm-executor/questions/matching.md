# How the Computer Itself Works as an Algorithm Executor — matching

Match each item on the left with the one it belongs to on the right.

**1. (Sub lesson 1) What is the computer's execution cycle?** → **Fetch the next instruction, decode it, execute it — then fetch the next**

**2. (Sub lesson 1) What keeps the place in the program?** → **The program counter, pointing at the next instruction**

**3. (Sub lesson 1) Which part runs the cycle?** → **The processor**

**4. (Sub lesson 1) Do branches and loops break the cycle?** → **No — they redirect the program counter; the cycle itself is the same**

**5. (Sub lesson 1) How fast does the cycle run?** → **Billions of times per second — the same three steps each time**

**6. (Sub lesson 2) What is the computer's command set like?** → **Small and exact — machine instructions**

**7. (Sub lesson 2) Does the computer do what was meant or what was said?** → **What was said — its obedience is total and its judgement zero**

**8. (Sub lesson 2) Name the computer's two inhuman strengths.** → **Speed and endurance**

**9. (Sub lesson 2) Why must the algorithm be complete before running?** → **The executor never tires but also never thinks — it cannot repair gaps**

**10. (Sub lesson 2) Can the computer notice a senseless instruction?** → **No — it executes it as written**
