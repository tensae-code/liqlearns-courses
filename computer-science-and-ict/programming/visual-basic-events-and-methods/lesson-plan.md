## Sub lessons
The parts of this lesson, in order — the list the learner sees from the start, locked ahead, each opening when the one before it is proved:

1. **Events — the happenings a program answers** — An **event** is a **happening the program can respond to**: the user **clicks** a button, a form **loads**, a key is pressed, a value changes. The programmer writes the code for an event in that event's **procedure**, and the program runs it **when the event happens** — event-driven programming, the shape every Visual Basic form already taught in this course has been using. Naming the event is naming **when** the code runs.
2. **Methods, and property against function** — A **method** is an **action an object can be told to perform** — told in code, with the object's name: the object does something. A **property**, by contrast, is a **characteristic** an object has — its text, colour, position — a value it holds, not an action it does. And the book draws the second line plainly: a **property holds**; a **function works out and returns a value**. Event (when), method (do), property (has), function (returns) — four words, four different kinds of thing, and confusion between them is the beginner's main fog in this course.
