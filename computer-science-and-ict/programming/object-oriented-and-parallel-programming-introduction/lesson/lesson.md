# Object-Oriented and Parallel Programming — Introduction

## Do it first

Ch.6 ends the course's survey of what programming can be: after the structured road it has walked all year, it opens two doors — objects, and parallelism — and names the environments where each is worked.

## Sub lesson 1 — Object-oriented programming — the world as objects

The **object-oriented** introduction restates the shift the course's later chapter teaches fully: a program is designed as **objects** — things holding their **data (properties)** and their **actions (methods)** together — which **send messages** to each other instead of marching through one list of commands over naked data. The introduction's job is the map: objects, classes, and the promise that big worlds (a school, a shop, a game) model themselves more honestly as societies of things than as one long procedure.

In your mind's eye: object-oriented programming — the world as objects.

## Sub lesson 2 — Parallel programming — several things at once

**Parallel programming (παράλληλος προγραμματισμός)** writes programs whose parts run **at the same time** — splitting a heavy job across processors that work together, so the wall-clock time falls where the job truly divides. Its new difficulty is the introduction's warning: parts running together must **coordinate** — share data carefully, wait for each other at the right joins — or the speed is bought with answers that change from run to run. The chapter closes with the **programming environments** where each road is worked, the course's bridge from languages to the places programmers actually write them.
