# Program Structure — Modules, Libraries and APIs — matching

Match each item on the left with the one it belongs to on the right.

**1. (Sub lesson 1) What is a module?** → **A named part of a program with one job, hiding its insides and showing a small surface**

**2. (Sub lesson 1) What is a library?** → **A collection of ready modules written by others, imported instead of invented**

**3. (Sub lesson 1) Why divide a program into modules?** → **Each part can be built, tested and fixed on its own — and reused**

**4. (Sub lesson 1) What does a module hide, and what does it show?** → **It hides its insides; it shows a small surface the rest may use**

**5. (Sub lesson 1) Where is this structure named in Armenia's course?** → **The Grade 11 programme outcomes in the teacher guide (p. 44)**

**6. (Sub lesson 2) What is an API?** → **The written agreement at a part's surface — the operations offered, what each needs, and what each returns**

**7. (Sub lesson 2) What do callers promise, and what do makers promise?** → **Callers ask only through the API; makers may change the insides while the API holds**

**8. (Sub lesson 2) Why does the API promise matter?** → **It lets parts be improved or rebuilt without breaking everyone who uses them**

**9. (Sub lesson 2) Give an everyday analogy for an API.** → **A counter in a shop: you ask at the counter by the menu; the kitchen behind it may reorganise freely**

**10. (Sub lesson 2) Name one API you have used without coding.** → **Any service's public interface — for example a weather service other programs query**
