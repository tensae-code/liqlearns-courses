## Sub lessons
The parts of this lesson, in order — the list the learner sees from the start, locked ahead, each opening when the one before it is proved:

1. **Modules and libraries — dividing and supplying** — A program of any size is divided into **modules**: named parts, each with one job, each hiding its insides and showing a small surface to the rest. Ready modules written by others are gathered into **libraries** — collections a programmer imports instead of inventing (maths libraries, graphics libraries, a school system's date library). Armenia's Grade 11 programme names program structure among its outcomes: the guide's programme (p. 44) expects learners to know how a program is built from modules, libraries and APIs. (This lesson stands on that guide evidence — see sources.)
2. **APIs — the agreement between parts** — An **API** (application programming interface) is the written agreement at a module's or service's surface: the names of the operations offered, what each needs, and what each returns. Callers promise to ask only through the API; makers promise the insides may change while the API holds. That promise is what lets a library be improved, a school system be rebuilt underneath its screens, and a map service serve a thousand programs it has never seen.
