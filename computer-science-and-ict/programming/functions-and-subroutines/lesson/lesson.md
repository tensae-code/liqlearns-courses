# Functions and Subroutines

## Do it first

A long program repeats its tricks. The grown-up answer is to name a trick once and call it by name. This lesson learns the naming — functions and subroutines.

## Sub lesson 1 — How a function works

A **function** is a named piece of program that does one job and can be **called** from many places. When called, the program **jumps** to the function's steps, works them, and **returns** to the place it was called from — carrying back a **result** if the job produces one. In the Scratch world of Jordan's Grade 9 unit, a function appears as a custom block: defined once with its name, then used as if Scratch had always had it. The point is economy of thought: the main program reads as a story of named jobs.

In your mind's eye: how a function works.

## Sub lesson 2 — Types, subroutines and parameters

Functions divide by their giving: some **return a value** (a computation's answer), some **do an act** and return nothing — these are often called **subroutines** (procedures): draw the house, play the fanfare. Both kinds take **parameters** — the values handed in at the call (draw the house *this big, here*) — which make one definition serve many cases. The lesson's closing distinction is the programmer's daily bread: a function is a job defined once; its parameters are how the job is fitted to each occasion; its call is how the program stays readable while doing much.

In your mind's eye: types, subroutines and parameters.
