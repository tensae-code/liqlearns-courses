## Sub lessons
The parts of this lesson, in order — the list the learner sees from the start, locked ahead, each opening when the one before it is proved:

1. **Following an algorithm step by step** — Read an unfamiliar algorithm the slow way: note what it asks for at the start (its **inputs**), then follow it line by line with small, easy values, writing down each variable's value as it changes — a **trace**. Note every decision and what makes the algorithm take each branch, and every loop and what makes it stop. The trace is the algorithm thinking out loud; without it, reading is guessing.
2. **Naming the task it performs** — With traces done on two or three different inputs, compare what went in with what came out each time: the pattern between input and output **is** the task — 'it adds the numbers from 1 to the number given', 'it finds the largest of the three values'. Say the task in one plain sentence naming the inputs and the result, then test your sentence: run one more value and check the algorithm does exactly what your sentence promises — no more, no less.

Gate pool: all questions of the sub lesson — no hardness ranking is written in questions/, so the sub lesson's whole question set is the gate pool.
