# Reading an Algorithm and Saying What It Does — multiple choice

Pick the one right answer.

**1. (Sub lesson 1) What do you note first in an unfamiliar algorithm?**
a) Its inputs — what it asks for at the start  b) Writing down each variable's value as it changes, step by step  c) Guessing  d) Run one more value and see whether the algorithm does exactly what it promises
**Answer: a) Its inputs — what it asks for at the start**

**2. (Sub lesson 1) What is a trace?**
a) Small, easy values  b) Writing down each variable's value as it changes, step by step  c) Compare what went in with what came out, across several traces  d) One trace shows one case; the pattern across traces shows the task
**Answer: b) Writing down each variable's value as it changes, step by step**

**3. (Sub lesson 1) Which values should a first trace use?**
a) Every decision and its branch condition, and every loop and what stops it  b) In one plain sentence naming the inputs and the result  c) Small, easy values  d) More — or less — than the algorithm actually does
**Answer: c) Small, easy values**

**4. (Sub lesson 1) What two structures must you note as you read?**
a) Guessing  b) Run one more value and see whether the algorithm does exactly what it promises  c) Its inputs — what it asks for at the start  d) Every decision and its branch condition, and every loop and what stops it
**Answer: d) Every decision and its branch condition, and every loop and what stops it**

**5. (Sub lesson 1) Reading without a trace is…**
a) Guessing  b) Compare what went in with what came out, across several traces  c) One trace shows one case; the pattern across traces shows the task  d) Writing down each variable's value as it changes, step by step
**Answer: a) Guessing**

**6. (Sub lesson 2) How do you find the task an algorithm performs?**
a) In one plain sentence naming the inputs and the result  b) Compare what went in with what came out, across several traces  c) More — or less — than the algorithm actually does  d) Small, easy values
**Answer: b) Compare what went in with what came out, across several traces**

**7. (Sub lesson 2) How should the task be said?**
a) Run one more value and see whether the algorithm does exactly what it promises  b) Its inputs — what it asks for at the start  c) In one plain sentence naming the inputs and the result  d) Every decision and its branch condition, and every loop and what stops it
**Answer: c) In one plain sentence naming the inputs and the result**

**8. (Sub lesson 2) How do you check your sentence about the task?**
a) One trace shows one case; the pattern across traces shows the task  b) Writing down each variable's value as it changes, step by step  c) Guessing  d) Run one more value and see whether the algorithm does exactly what it promises
**Answer: d) Run one more value and see whether the algorithm does exactly what it promises**

**9. (Sub lesson 2) Why trace more than one input?**
a) One trace shows one case; the pattern across traces shows the task  b) More — or less — than the algorithm actually does  c) Small, easy values  d) Compare what went in with what came out, across several traces
**Answer: a) One trace shows one case; the pattern across traces shows the task**

**10. (Sub lesson 2) What must your sentence not claim?**
a) Its inputs — what it asks for at the start  b) More — or less — than the algorithm actually does  c) Every decision and its branch condition, and every loop and what stops it  d) In one plain sentence naming the inputs and the result
**Answer: b) More — or less — than the algorithm actually does**
