## Sub lessons
The parts of this lesson, in order — the list the learner sees from the start, locked ahead, each opening when the one before it is proved:

1. **Simplicity and flexibility — how it reads, how it bends** — A program is **simple (απλότητα)** when its solution is no more tangled than its problem — clear structure, no needless cleverness, a reader's road straight. It is **flexible (ευελιξία)** when the changes life will surely ask — a new limit, a new case, a new tax rate — can be made **in one place**, in the constants and structures built for change, instead of by surgery everywhere. The two criteria pull together: the simple program is usually the one that bends without breaking.
2. **Reliability and speed — how it stands, how it runs** — A program is **reliable (αξιοπιστία)** when it gives the **right answer under the conditions it will truly meet** — awkward inputs, honest mistakes by users, long runs — not only under the demonstration's kind ones. It has **speed (ταχύτητα)** when its work finishes in the time its job allows, a criterion judged by its algorithm's growth (the performance chapter) and not by hope. The chapter's verdict form is the four together: a program passing all four is finished; one failing any is a draft with a name to fix.
