## Sub lessons
The parts of this lesson, in order — the list the learner sees from the start, locked ahead, each opening when the one before it is proved:

1. **Several loops, each with its own job** — A program may hold **many loops, one after another**, each repeating its own part: the mouse crosses a corridor (loop), turns a square room's corners (another loop), then climbs stairs (a third). Each loop keeps **its own body and its own count**; when one loop finishes, the program moves to the next instruction, loop or not. Reading such a program means reading it **in order, part by part** — and writing one means cutting the task into parts first, then looping the parts that repeat.
2. **The laboratory — compose, run, fix, and two new instructions** — The laboratory lessons work as real programming works: **compose** a program for a set task, **run** it on the executor, **find** where it went wrong, **fix** it and run again. Two new instructions join the executors' language here — **collect** and **squeeze** style orders for the hedgehog's tasks (gathering what lies on the road, passing narrow places) — met the laboratory way: an instruction is learned by the task that needs it. The module's closing rule: a program is finished not when it is written, but when it **runs right**.

Gate pool: all questions of the sub lesson — no hardness ranking is written in questions/, so the sub lesson's whole question set is the gate pool.
