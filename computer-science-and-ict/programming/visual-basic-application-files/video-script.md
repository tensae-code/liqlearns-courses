# Video script — Visual Basic Application Files

The super-simple voice, for the video that rides on top of the lesson (lesson-plan.md, add-on list). Made later, when videos are made; the script is the slot's written form until then.

---

A Visual Basic application is saved as a **project**: a **project file** that lists and binds the application's parts, and one **form file for each window** of the program — each form holding its design (the controls laid out on it) and its code together. Supporting files travel with them: modules of shared code, and the pictures or other resources the forms use. Fiji opens here deliberately: the application *is* this set, and losing a part loses a piece of the program.
When the application is finished it is **compiled** into a single **executable file** — the program the user actually runs, which no longer needs Visual Basic itself to open. The two shapes must not be confused: the **project files** are the workshop, kept by the programmer and opened to change the application; the **executable** is the product, given to users. Fiji's file lesson is the programmer's housekeeping oath: keep the project safe, for the executable can be remade from it — but the project can never be remade from the executable.
