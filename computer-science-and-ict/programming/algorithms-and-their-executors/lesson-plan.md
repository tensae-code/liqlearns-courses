## Sub lessons
The parts of this lesson, in order — the list the learner sees from the start, locked ahead, each opening when the one before it is proved:

1. **The executor — who carries the algorithm out** — An **executor** is the one who **carries out an algorithm's instructions**: a person following a recipe, a trained animal, a robot, or a computer running a program. Each executor has a **fixed set of commands it understands** — its command system — and an environment it can act in. The books' teaching executors make this concrete: the **Kangaroo** jumps its squares, the **Ant** follows its grid orders; an instruction outside the executor's set is not 'hard' — it is **meaningless** to it, and the algorithm fails at that line.
2. **Manual and program control — two ways to command** — An executor can be commanded two ways. Under **manual control**, a human gives each command one by one, watching each result — slow, flexible, and consuming the human the whole time. Under **program control**, the whole sequence is written in advance as an **algorithm (a program)**, and the executor runs it alone: fast, exact, and tireless, but only as right as the written sequence. Programming exists because program control frees the human from the commanding — at the price of having to think of everything beforehand.
