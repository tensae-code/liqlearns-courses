# Quantities in an Algorithm — Name, Value and Type

## Do it first

Before flowcharts, Mongolia's Grade 9 algorithm strand names what algorithms work on. A quantity is not a blur: it has a name you call it by, a value it holds, and a type that rules what may be done with it — and the book proves it on a horse.

## Sub lesson 1 — Name, value, type — the three faces of a quantity

A **quantity** in an algorithm is known by three faces. Its **name**: the word the algorithm calls it by — rope, radius, area. Its **value**: what it holds at this moment — 5 metres, 78.5 square metres — which may change as the algorithm runs. Its **type**: the kind of value it is — a number, a text, a yes/no — which decides what operations make sense on it. Confuse the faces and the algorithm breaks in the three classic ways: calling a quantity never named, trusting a value never set, working a text as if it were a number.

## Sub lesson 2 — The tethered horse — one problem, three tellings

The book's example is Mongolian to the bone: a **horse tethered** by a rope grazes a circle of steppe — how large is its pasture? The problem is worked **in words** first (the grazing ground is a circle; its radius is the rope), then **as a model** (area from radius by the circle rule), then **in Turtle Art**, where the drawing blocks walk the circle the horse walks. Same quantities — rope, radius, area — in all three tellings: the horse teaches that an algorithm's quantities survive every change of clothing, from words to model to machine.
