# Visual Programming Languages — Building with Pictures

## Do it first

Before Kuwait's Grade 12 pupils build in Visual Basic, their book places the language on a map: programming languages have levels, and one family of them is built with pictures. This lesson is that map.

## Sub lesson 1 — The levels of programming languages

Programming languages stand in **levels** by their distance from the machine: **low-level** languages speak nearly the machine's own tongue — fast and exact, hard and unforgiving for humans; **high-level** languages speak nearer the **human's** tongue — readable words and structures, translated to the machine by compilers and interpreters. A language's level is its bargain: the lower, the more control and the more labour; the higher, the more help and the less say over the machine's details. Visual Basic stands on the high level — which is why a school course can begin there.

## Sub lesson 2 — Visual programming languages — building with pictures

A **visual programming language** lets the programmer build **graphically**: the program's interface is drawn — forms and controls placed with the mouse — and parts of its behaviour are assembled visually, with code written where behaviour must be said in words. Visual Basic is the book's exemplar: the pupil **sees** the program while building it, because the window being built is on the desk during the building. The lesson's point is taxonomic courage: 'visual' names how the language is **worked**, a different axis from its level — a language can be both high-level and visual, and VB is both.
