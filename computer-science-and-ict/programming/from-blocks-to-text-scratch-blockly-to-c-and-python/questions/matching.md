# From Blocks to Text — Scratch and Blockly to C and Python — matching

Match each item on the left with the one it belongs to on the right.

**1. (Sub lesson 1) What is the transition this lesson teaches?** → **From visual block programming (Scratch, Blockly) to textual programming (C, Python)**

**2. (Sub lesson 1) What does not change across the crossing?** → **The structures — sequence, selection, repetition, variables, procedures — with the same meaning**

**3. (Sub lesson 1) What changes?** → **The spelling — shapes become syntax: words, punctuation and indentation that must be exact**

**4. (Sub lesson 1) Why can text fail where blocks cannot?** → **No palette prevents a malformed program in text; the text simply fails**

**5. (Sub lesson 1) How is the crossing made?** → **Translation first — rewrite a working block program line by line in text, running both until they agree**

**6. (Sub lesson 2) What is a translated block program, for the text version?** → **A known-correct plan**

**7. (Sub lesson 2) What block habits must be kept in text?** → **One structure at a time, meaningful names, testing as you go**

**8. (Sub lesson 2) The learner leaves owning the structures how many times?** → **Twice — once by shape, once by spelling**

**9. (Sub lesson 2) Which ownership do later languages ask for?** → **The second — by spelling**
