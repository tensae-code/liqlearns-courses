**The one thing this lesson teaches:** A **counter** is a variable that **counts by adding 1** each time something happens; an **accumulator** is a variable that **adds up values** — each new value is added into a running total.

## Sub lessons
The parts of this lesson, in order — the list the learner sees from the start, locked ahead, each opening when the one before it is proved:

1. **Counters — one more, each time** — A **counter** starts at an opening value — usually **zero** — and every time the event it watches happens, it **grows by exactly 1**: counter = counter + 1. At any moment the counter **tells how many times** the event has happened so far: pupils entered, pages read, goals scored. The counter does not care what happened, only how often. Forgetting to start it — or starting it at the wrong value — is the classic counter fault: every count after is off by that much.
2. **Accumulators — a running total** — An **accumulator** also starts opened — usually at **zero** — but it grows by **the value that arrives**: total = total + new value. It answers not how many, but **how much altogether**: the sum of marks, the cost of the shopping, the litres used. Counter and accumulator usually work side by side in one loop — the counter counts the values while the accumulator totals them — and together they give the average: total ÷ count. Cuba pairs them in one section because real programs so rarely use one without the other.

4. By the value that arrives, not by 1.
