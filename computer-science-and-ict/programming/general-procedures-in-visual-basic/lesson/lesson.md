# General Procedures in Visual Basic

## Do it first

A program that does the same job in five places should write the job once. Fiji's Year 12 Visual Basic course gives that writing its own section: general procedures — code with a name, called from wherever it is needed. This lesson is the writing and the calling.

## Sub lesson 1 — A procedure — a named piece of program

A **procedure** is a **named block of code that does one job**, written once and **called** by name whenever the job is needed. Fiji divides them by what they hand back: a **Sub** procedure **does** the job and returns nothing; a **Function** procedure **works out a value and returns it** to the caller. Values the job needs are **passed in** as the call's arguments, so the same procedure works on different data each time it is called.

In your mind's eye: a procedure — a named piece of program.

## Sub lesson 2 — Why procedures — write once, fix once

The gains are the programmer's daily bread. **Write once**: the job exists in one place, not copied into every button that needs it. **Fix once**: correct the procedure and every call is corrected with it. **Read clearly**: the calling program says *what* happens — the procedure's name — while the procedure itself says *how*. Fiji places general procedures late in the chapter because they are where a collection of event code becomes an organised program: the same discipline its good-applications section demanded, now with a tool.
