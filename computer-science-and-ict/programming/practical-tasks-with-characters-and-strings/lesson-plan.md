# Lesson plan — Practical Tasks with Characters and Strings

**Course:** Computer Science and ICT · **Title:** Programming · **Lesson:** Practical Tasks with Characters and Strings
**Place in the curriculum:** ICT expansion — Belarus (2026-11-14) — in the title Programming on the ICT course ladder (TITLES.md). Built new from Belarus's *Інфарматыка* Grade 10, because no existing lesson in the course covers this thing as its own lesson.
**The one thing this lesson teaches:** Practical string work means solving a whole task end to end — read the text, plan which character and string tools the job needs, write the program, and test it on cases that include the awkward ones.
**This lesson's own level:** It stands on the earlier lessons of its title and on the Belarus book's own order — it follows the book's sections in sequence, so its neighbours in the book are its natural companions. It stands alone for a learner landing on it directly.

A lesson plan also says **what goes on top of the lesson**: at the exact places marked below, the lesson page carries an add-on — an image, a GIF, a video, an audio. Every slot is written as **"a picture of …" in words, plus one little line saying what the student does with it**. The words carry the picture while the course is built and while the AI learns from the books; on the website the real add-on is dropped into that slot and the little explanation stays as the student's guide. ## Sub lessons
The parts of this lesson, in order — the list the learner sees from the start, locked ahead, each opening when the one before it is proved:

1. **From tools to whole tasks** — The earlier sections gave the pieces: **char** and codes, the **string** type, and the string **procedures and functions**. A **practical task** joins them into one job with an input and a required result — count the letters in a text, build initials from a full name, check how a word is made, rearrange parts of a sentence. The first step is not writing code: it is saying exactly what goes in, what must come out, and which tools from the kit do each part of the change.
2. **Testing the finished program** — A program that works on one easy text may still be wrong. **Testing** means running it on chosen cases: an ordinary case, a short case (one word, one character), and an awkward case (an empty text, extra spaces, a piece that is not found). Each test compares the program's result with the result worked out by hand. When a test fails, the fault is hunted in the plan first — the wrong tool, a position off by one, an edge the plan forgot — and only then in the typing. A task is finished when its tests pass, not when its program merely runs.

Gate pool: all questions of the sub lesson — no hardness ranking is written in questions/, so the sub lesson's whole question set is the gate pool.

1. A practical task — one job with an input and a required result.
2. Counting letters in a text, or building initials from a full name.
3. An empty text, extra spaces, or a piece that is not found.
4. The char, string, and string procedure/function tools from the earlier sections.

Paper and a pencil, and a computer with the program this lesson uses, if available.
