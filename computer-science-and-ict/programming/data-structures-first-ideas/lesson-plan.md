# Lesson plan — Data Structures — First Ideas

**Course:** Computer Science and ICT · **Title:** Programming · **Lesson:** Data Structures — First Ideas
**Place in the curriculum:** ICT expansion — North Macedonia (2026-11-14) — in the title Programming on the ICT course ladder (TITLES.md). Built new from North Macedonia's *Informatics* (2026), because no existing lesson in the course covers this thing as its own lesson.
**The one thing this lesson teaches:** A data structure is an organised way of holding a collection of data so a program can work with it — values kept together under rules (a row, a list, a stack) instead of scattered in separate variables; choosing the structure is choosing what the program can easily do with the data.

## Sub lessons
The parts of this lesson, in order — the list the learner sees from the start, locked ahead, each opening when the one before it is proved:

1. **Collections need organisation** — Programs rarely hold one value: they hold **collections** — many marks, many names, many measurements. A **data structure** is the **organised form** the collection is kept in: the values together, under rules that say how items are added, found and taken out. Separate variables are the absence of structure: fine for three values, hopeless for three hundred.
2. **First shapes to recognise** — The first shapes are the **array** (a row picked by position — this course's working structure), the **stack** idea (last in, first out, like a pile of plates) and the **queue** idea (first in, first out, like a line at a till). The book plants the idea early (Year 1, §3.2) before the structures themselves arrive, because every later data lesson is a structure lesson in disguise.
