# Data Structures — First Ideas

## Do it first

One value fits in one variable. A hundred values need organisation. This short lesson opens the idea that the rest of the programming course keeps using.

## Sub lesson 1 — Collections need organisation

Programs rarely hold one value: they hold **collections** — many marks, many names, many measurements. A **data structure** is the **organised form** the collection is kept in: the values together, under rules that say how items are added, found and taken out. Separate variables are the absence of structure: fine for three values, hopeless for three hundred.

## Sub lesson 2 — First shapes to recognise

The first shapes are the **array** (a row picked by position — this course's working structure), the **stack** idea (last in, first out, like a pile of plates) and the **queue** idea (first in, first out, like a line at a till). The book plants the idea early (Year 1, §3.2) before the structures themselves arrive, because every later data lesson is a structure lesson in disguise.

## Say it to your companion

Tell your companion, in your own words: A data structure is an organised way of holding a collection of data so a program can work with it — values kept together under rules (a row, a list, a stack) instead of scattered in separate variables; choosing the structure is choosing what the program can easily do with the data. Then let your companion ask you one question about it — and answer from the lesson, not from memory of the book's exact words.
