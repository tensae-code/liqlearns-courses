## Sub lessons
The parts of this lesson, in order — the list the learner sees from the start, locked ahead, each opening when the one before it is proved:

1. **Pseudocode — plain words, machine precision** — **Pseudocode** is an algorithm written in **short, ordered, unambiguous instructions** in ordinary words — 'SET cup on table', 'POUR water UNTIL full' — no special language, but no vagueness either: every step names one action, every decision names its condition, every repeat names its end. It is 'pseudo' because it is not code a computer runs directly; it is the programme's thinking, written where humans can read, check and argue with it before any real language is touched.
2. **Let the machine read our words — running pseudocode in the robot** — The Grade 7 sessions **run the pseudocode in a robot** — a learner (or the book's Nano) executes the class's instructions **literally**: a missing step is a fall, a vague word is a frozen robot, an endless instruction is a robot walking into the wall forever. The failures are the teaching: each one sends the writers back to their text to find the exact word that failed, and the rewrite is the debugging lesson arriving early, in plain language. Pseudocode that survives a literal reader is ready to become a real program — the flowchart lesson's twin, in words instead of shapes.

Gate pool: all questions of the sub lesson — no hardness ranking is written in questions/, so the sub lesson's whole question set is the gate pool.

## The run of the lesson (in order)
1. **Do it first** — 'Make tea' is an instruction a human survives and a machine fails at the first word — which tea, in what, heated how? Grade 7's robot sessions teach the cure: pseudocode, instructions written in plain words but with a machine's literalness. This lesson writes them, then runs them on the strictest computer available — a classmate obeying exactly, and only, what is written. (lesson/lesson.md).
