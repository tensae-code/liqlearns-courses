## Sub lessons
The parts of this lesson, in order — the list the learner sees from the start, locked ahead, each opening when the one before it is proved:

1. **Understand and plan before building** — Development opens away from the keyboard: **understand the problem** — what the program must do, what goes in and what must come out — then **plan the steps** (the algorithm, in pseudocode or flowchart) that turn the input into the output. Only then is the program **built** — written in the language or blocks the project uses, following the plan. Malaysia's order is the discipline: a program built from a plan can be checked against the plan; a program built from a guess can only be checked against another guess.
2. **Test, fix, and test again** — A built program is **tested**: run with known inputs whose right outputs are already worked out by hand, and the program's outputs compared. A mismatch is a **fault found**, not a failure of the whole work — the fault is located, **fixed**, and the program tested again, including the tests that passed before, because a fix can break a neighbour. Development ends when the tests pass and the program does the understood problem's job — the staircase's top is the problem you started with, solved.

## The run of the lesson (in order)
1. **Do it first** — A program is not typed in one rush from a blank screen. Malaysia's Grade 7 book teaches program development as a staircase of steps, climbed in order. In this lesson you learn the staircase — and why skipping steps is what makes programs fail. (lesson/lesson.md).
2. **The explanation** — the lesson text in lesson/lesson.md, in its parts in order.
