# Developing a Program Step by Step — matching

Match each question on the left with its answer on the right. Write the letter beside each number.

1. (Sub lesson 1) What are the development steps, in order?
2. (Sub lesson 1) What must be understood first?
3. (Sub lesson 1) In what forms is the plan written?
4. (Sub lesson 1) Why build from a plan?
5. (Sub lesson 1) When is the program built?
6. (Sub lesson 2) How is a program tested?
7. (Sub lesson 2) What is a mismatch in testing?
8. (Sub lesson 2) After a fix, which tests are run again?
9. (Sub lesson 2) When does development end?
10. (Sub lesson 2) What does skipping steps cause?

a) What the program must do — what goes in and what must come out
b) A planned program can be checked against its plan; a guessed one only against another guess
c) Understand the problem, plan the steps, build the program, test it, fix what the tests expose
d) After understanding and planning — third, not first
e) Pseudocode or flowchart — the algorithm
f) A fault found — located and fixed, not a failure of the whole work
g) When the tests pass and the program does the understood problem's job
h) Run with known inputs whose right outputs are worked out by hand, and compare
i) Programs that fail — the staircase exists because each step feeds the next
j) All of them — including ones that passed, because a fix can break a neighbour
