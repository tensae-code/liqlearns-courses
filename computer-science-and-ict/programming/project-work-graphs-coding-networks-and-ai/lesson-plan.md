# Lesson plan — Project Work — Graphs, Coding, Networks and AI

**Course:** Computer Science and ICT · **Title:** Programming · **Lesson:** Project Work — Graphs, Coding, Networks and AI
**Place in the curriculum:** ICT expansion — Germany (2026-11-14) — in the title Programming on the ICT course ladder (TITLES.md). Built new from Germany's *Informatik 5 (Bayern NTG)*, because no existing lesson covers this thing as its own lesson.
**The one thing this lesson teaches:** a project turns the strand's knowledge into a made thing: it is planned like real work — goal, plan, roles, milestones, a check against the goal at the end — and this book's menu offers one build per strand (a graph route-finder, a coding/cipher tool, a network investigation, an AI experiment), including its signature piece: programming a social bot.
**This lesson's own level:** It stands on the whole of Germany's four strands in this course — graphs, coding and cryptography, networks, AI — and is their capstone: nothing new is taught except the project craft itself; everything else is applied.

A lesson plan also says **what goes on top of the lesson**: at the exact places marked below, the lesson page carries an add-on — an image, a GIF, a video, an audio. Every slot is written as **"a picture of …" in words, plus one little line saying what the student does with it**. The words carry the picture while the course is built and while the AI learns from the books; on the website the real add-on is dropped into that slot and the little explanation stays as the student's guide. GIFs come first where a thing must be shown moving — a GIF here is 1–2 seconds.

## Sub lessons
The parts of this lesson, in order — the list the learner sees from the start, locked ahead, each opening when the one before it is proved:

1. **Planning a project — goal, steps, roles, milestones** — Project management in school size: fix the goal as a checkable sentence; break the work into steps with owners (roles); set milestones — dated points where a named piece must exist; keep a simple log; at the end, test the product against the goal sentence and present what was made and what failed.
2. **The menu — one build per strand, and the social bot** — The chapter's proposals: a graph build (route-finder on a real map), a coding build (a cipher tool or code-breaking challenge), a networks build (map and explain the school/home network), an AI build (train a small classifier and test it honestly). Crown piece: programming a social bot — pattern rules that read a message and answer in character; which strands it touches (coding of text, decision rules, limits of rule-based replies against learned ones).

Gate pool: all questions of the sub lesson — no hardness ranking is written in questions/, so the sub lesson's whole question set is the gate pool.

## Before this lesson
- Recommended first: the Germany strand lessons in this course — graphs and Dijkstra, coding and encryption, networks, and the AI lessons through Neural Networks. Recommended, never forced — a learner may land on this lesson directly, and it stands alone.

## What the learner can do when it ends
1. Write a one-page project plan: goal, steps, roles, milestones, and how success will be checked.
2. Choose a menu project and say which strand knowledge it uses, piece by piece.
3. Describe what a simple rule-based social bot does, message by message.

## What you need
A team of two to four, paper for the plan, and whatever the chosen build needs — most menu projects run on paper, a school computer, or a phone. Time is the real material: the plan divides it before the work eats it.

## If the learner is stuck
Goal written as a topic ('about AI') → a goal is a checkable sentence: a product plus the test it must pass. Bot judged as 'stupid' when it misses a message → an unmatched message is data: log it, and the log is the project's finding about rule-based systems.
