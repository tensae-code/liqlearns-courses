# Combining Search or Sort

## Do it first

Not every combination is sort-then-search. Malaysia's chapter closes by putting the choice itself on the table: some jobs need only a search, some only a sort, and some weave the two the other way round. In this lesson you learn to read a job and know which it is.

## Sub lesson 1 — Reading the job — search, sort, or both

The choice is read off the job's **question**. A job asking **whether or where** a value is — with no need for the list afterwards in order — is a **search** job. A job asking for the list **itself in order** — a ranking, a timetable, a price line — is a **sort** job. A job asking repeated where-questions **and** an ordered list is **both**. Malaysia's discipline is to refuse the unneeded half: sorting a list to answer one where-question wastes the sort; searching a list that must be handed over ordered leaves the job undone.

## Sub lesson 2 — The other weaving — each inside the other

The two also live **inside** each other: sorting methods **search** as they work (bubble sort's passes search for out-of-order pairs; finding the smallest remaining value is a search repeated inside a selection-style sort), and a search can be **served by a partial sort** (bucket sort's scattering is a search-by-size that half-sorts as it places). Recognising the inner job explains the outer one's cost: a sort built on repeated searching takes repeated-search time. The chapter's final skill is this reading — naming the jobs inside the job before choosing the algorithm.
