## Sub lessons
The parts of this lesson, in order — the list the learner sees from the start, locked ahead, each opening when the one before it is proved:

1. **Questions that split the world** — A **decision tree (arbre de décision)** sorts by questions: each **yes–no question** splits the remaining candidates into two piles, the answer chooses the branch, and the next question splits again — until each leaf holds one name. The complementary séance builds the tree for Square CT's houses: criteria become questions (roof colour? two floors? chimney?), and a good question is one that **splits the pile usefully** — near half and half beats a question that isolates one house and leaves nineteen.
2. **Trees are programs you can draw** — Read downward, a decision tree **is** a program: question = a test, branch = a path, leaf = an answer — the flowchart's family, grown as a tree. Identification games, fault-finding charts and classification keys in science are all this one shape. Building the tree teaches the deep economy of asking: with perfect splitting, twenty questions can name a million things — each answer doubling what you can distinguish.

Gate pool: all questions of the sub lesson — no hardness ranking is written in questions/, so the sub lesson's whole question set is the gate pool.
