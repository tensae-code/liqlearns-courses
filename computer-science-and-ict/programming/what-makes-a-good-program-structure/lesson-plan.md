# Lesson plan — What Makes a Good Program — Structure

**Course:** Computer Science and ICT · **Title:** Programming · **Lesson:** What Makes a Good Program — Structure
**Place in the curriculum:** ICT expansion — Bangladesh (2026-11-14) — in the title Programming on the ICT course ladder (TITLES.md). **The one thing this lesson teaches:** the structure of a good program: readable, free of endless loops, ending in a precise final answer, and efficient with memory — the four tests a program must pass before it is called good (Bangladesh HSC ICT, Chapter 5, §5.3).

## Sub lessons
The parts of this lesson, in order — the list the learner sees from the start, locked ahead, each opening when the one before it is proved:

1. **Readable — and always ending** — A good program is **readable**: names that mean, structure that shows, comments where the thinking is dense — because programs are read by people far more than they are run by machines. And it **ends**: no **endless loop** waits inside it — every repeat carries the change that brings its condition false, tested in the mind for the inputs that might starve it. A program that might hang has not finished being written, however beautiful its output today.
2. **Precise answers — and memory respected** — A good program gives a **precise final answer**: not approximately, not sometimes — the exact result the problem asked, for the whole range of honest inputs, with the dishonest ones refused as the calculator lesson designed. And it is **efficient with memory**: variables sized to their job, no arrays of a million for a class of thirty, no copies kept from laziness — memory is the machine's shared purse, and the good program spends it like a guest, not an owner. Four tests — readable, ending, precise, frugal — one program, judged whole.
