# What Makes a Good Program — Structure — short answer

Answer in a short sentence of your own.

**1. (Sub lesson 1) Name the four tests of a good program.**
**Answer: Readable, always ending, precise answers, memory-efficient**

**2. (Sub lesson 1) Why must a program be readable?**
**Answer: Programs are read by people more than run by machines**

**3. (Sub lesson 1) What three things make code readable?**
**Answer: Meaningful names, showing structure, comments where thinking is dense**

**4. (Sub lesson 1) What must every loop carry?**
**Answer: The change that brings its condition false**

**5. (Sub lesson 1) When is a program that might hang finished?**
**Answer: Never — it is not finished being written**

**6. (Sub lesson 2) What answer must a good program give?**
**Answer: A precise final answer — exact, for all honest inputs**

**7. (Sub lesson 2) How are dishonest inputs handled?**
**Answer: Refused, as designed**

**8. (Sub lesson 2) What does memory-efficient mean?**
**Answer: Variables sized to their job, no wasteful copies**

**9. (Sub lesson 2) Whose purse is memory, in the lesson's image?**
**Answer: The machine's shared purse — spend it like a guest**

**10. (Sub lesson 2) Can a program pass three tests and fail as good?**
**Answer: Yes — it is judged whole, on all four**
