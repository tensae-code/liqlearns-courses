# Lesson plan — Visual Basic — Starting a Project and Adding Controls

**Course:** Computer Science and ICT · **Title:** Programming · **Lesson:** Visual Basic — Starting a Project and Adding Controls
**Place in the curriculum:** ICT expansion — Kuwait (2026-11-14) — in the title Programming on the ICT course ladder (TITLES.md). Built new from Kuwait's student books (Ministry of Education, State of Kuwait), because no existing lesson in the course covers this thing as its own lesson — the live tree and live lesson content were checked for the slug and for near matches before building.
**The one thing this lesson teaches:** Planning a Visual Basic program, creating a new project, and adding controls to its form — the first chapter of Kuwait's 'Stages of Building a Program'
**This lesson's own level:** It stands on the earlier lessons of its title and on the book's own order — it follows the book's lessons in sequence, so its neighbours in the book are its natural companions. It stands alone for a learner landing on it directly.

A lesson plan also says **what goes on top of the lesson**: at the exact places marked below, the lesson page carries an add-on — an image, a GIF, a video, an audio. Every slot is written as **"a picture of …" in words, plus one little line saying what the student does with it**. The words carry the picture while the course is built and while the AI learns from the books; on the website the real add-on is dropped into that slot and the little explanation stays as the student's guide. GIFs come first where a thing must be shown moving — a GIF here is 1–2 seconds.

## Sub lessons
The parts of this lesson, in order — the list the learner sees from the start, locked ahead, each opening when the one before it is proved:

1. **Planning the program — before the project exists** — Kuwait's building book opens with **planning**: what the program is **for**, what its window must **show**, and what its user will **do** — decided on paper before a project is created. The plan is short and it is first, because a form built without it collects controls the way a desk collects papers. The series' project discipline (goal, then plan, then build) is the same craft at this smaller scale: the stages of building a program begin with a stage that touches no computer.
2. **Creating the project and adding controls to the form** — The plan becomes a **new project** in the environment, and its **form** — the program's window — is populated by **adding controls**: each control taken from the toolbox and **placed** on the form, then positioned and sized where the plan wants it. Adding is the visual language's core verb: the interface is **assembled**, control by control, and the form on screen grows to look like the program it will be — before a line of code gives it behaviour.

Gate pool: all questions of the sub lesson — no hardness ranking is written in questions/, so the sub lesson's whole question set is the gate pool.
