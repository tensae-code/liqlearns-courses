## Sub lessons
The parts of this lesson, in order — the list the learner sees from the start, locked ahead, each opening when the one before it is proved:

1. **SELECT CASE — one value, many cases** — **SELECT CASE** names **one value or expression** to test, then lists **cases**: `Case 1`, `Case 2`, a **range** such as `Case 1 To 5`, or a **list** such as `Case 2, 4, 6`. The value is compared **once** against each case in order; the **first matching case's** statements run, and the statement ends — no later case runs. The whole structure closes with **END SELECT**, as IF closes with END IF.
2. **CASE ELSE and choosing SELECT CASE over IF** — **Case Else** is the case for **every value no other case matched** — the safety net, as Else is for IF. Choose SELECT CASE when the choice turns on **one value with many named possibilities** — a menu number, a mark band, a day of the week; keep IF for tests that are **about conditions**, especially different conditions on different values, and for the two-way choice. Libya teaches SELECT CASE inside its conditional-control chapter, after IF and the AND/OR connectors, as the third shape of choosing.

Gate pool: all questions of the sub lesson — no hardness ranking is written in questions/, so the sub lesson's whole question set is the gate pool.

## What the learner can do when it ends
1. One value or expression, matched against a list of cases
2. Once against each case, in order, until a case matches
3. That case's statements — and no later case runs
4. As a range (Case 1 To 5) or a list (Case 2, 4, 6)
