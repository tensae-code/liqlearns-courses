# Iterative Development of Software

## Do it first

The first version of almost everything is wrong in ways only use can reveal. Iterative development plans for that: build a little, learn, build again. This lesson learns the round-based way of growing software.

## Sub lesson 1 — What iterative development is

**Iterative development** builds software in **rounds (iterations)**: each round designs, builds and tests a **working version** — small, incomplete, but real — and the **feedback** from testing and using it shapes the next round. The approach stands against the single-pass plan (everything designed, then everything built, then everything discovered wrong at once): iteration spreads the discovering across the whole building, when repairs are still cheap.

In your mind's eye: what iterative development is.

## Sub lesson 2 — Working the rounds — in the Scratch unit

Jordan teaches iteration inside the Grade 9 Scratch work because Scratch makes rounds fast: a game is built, played, found too easy or broken at level two, **changed**, and played again — the loop of **build → test → improve** is the lesson's heartbeat. Each round ends with a decision the feedback earned: keep, fix, or drop a feature. The approach's discipline is that a round must end in a **working** version — 'nearly working' is where projects go to hide — and that feedback is collected on purpose (players observed, faults written), not awaited by chance.

In your mind's eye: working the rounds — in the Scratch unit.
