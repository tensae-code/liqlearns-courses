# Event Programming — When Something Happens — short answer

Answer in a short sentence of your own.

**1. (Sub lesson 1) How does a sequential program run?**
**Answer: Top to bottom, once, in order**

**2. (Sub lesson 1) What is an event program built of?**
**Answer: Reactions — ‘when this happens, do that’**

**3. (Sub lesson 1) What does an event program do between events?**
**Answer: It waits, alive to its events**

**4. (Sub lesson 1) Name two event examples.**
**Answer: Sensor sees obstacle → stop; button pressed → celebrate**

**5. (Sub lesson 1) Why does a real robot need both kinds?**
**Answer: Routes to run, and reflexes to survive them**

**6. (Sub lesson 2) How does VPL write an event program?**
**Answer: An event card paired with action cards**

**7. (Sub lesson 2) What crowns a Scratch event script?**
**Answer: An event block — green flag, key, click, sensor**

**8. (Sub lesson 2) Name the types the advanced remark compares.**
**Answer: Sequential, event-driven, and their mixtures**

**9. (Sub lesson 2) What kind of act is choosing the type?**
**Answer: A design act**

**10. (Sub lesson 2) Which tasks want events?**
**Answer: Tasks in a surprising world**
