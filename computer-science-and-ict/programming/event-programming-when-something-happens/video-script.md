# Video script — Event Programming — When Something Happens

The super-simple voice, for the video that rides on top of the lesson (lesson-plan.md, add-on list). Made later, when videos are made; the script is the slot's written form until then.

---

A **sequential program** runs its instructions top to bottom, once, in order — the Blue-Bot route, the drawing script. An **event program (programmation événementielle)** is built of **reactions**: ‘when this happens, do that’ — when the sensor sees an obstacle, stop; when the button is pressed, celebrate. It does not run out; it **waits**, alive to its events, answering each as it comes. The Décodage robot work teaches the pair together from Blue-Bot Séance 4–5 onward, because a real robot needs both: routes to run, and reflexes to survive them.
Every environment of the course speaks events in its own accent: **VPL** pairs an event card with action cards; **Scratch** crowns scripts with event blocks (green flag, key, click, sensor); interfaces everywhere wait for clicks and keys. The Grade 7 advanced remark pauses to name the **types of programming** side by side — sequential, event-driven, and their mixtures — because choosing the kind is a design act: tasks with a fixed story want sequence; tasks in a surprising world want events; most real programs, like Thymio's missions, marry the two.
