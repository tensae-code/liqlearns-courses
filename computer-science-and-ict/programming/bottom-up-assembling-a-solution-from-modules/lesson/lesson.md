# Bottom-up — assembling a solution from modules

## Do it first

Five shapes — circle, triangle, rectangle, cube, parallelogram — each needs its area and perimeter. Yesterday's lesson would start from the big problem and break it down. This lesson starts at the bottom: build each shape's module first, perfectly, then assemble. Which order feels safer when the pieces already exist?

## Building up

Bottom-up works exactly opposite to top-down: the most fundamental units, modules and sub-modules are designed and solved individually first, then integrated to form the more concrete solution. If modules with the needed functionality already exist, they are brought together; otherwise each is developed first and built up incrementally.

## The polygons example — and what both approaches share

The example: a program for areas and perimeters of many polygons (circle, triangle, rectangle, cube, parallelogram), assembled from per-polygon modules. Most real programs combine both strategies. And both rest on the same two habits: incremental development — building piece by piece — and unit testing — testing each piece before moving to the next.
