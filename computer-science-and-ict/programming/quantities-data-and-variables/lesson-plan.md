## Sub lessons
The parts of this lesson, in order — the list the learner sees from the start, locked ahead, each opening when the one before it is proved:

1. **Constants and variables — what may change** — A **quantity** is anything a program works with — a number, a text, a measurement. Quantities divide by one question: may the value change while the program runs? A **constant** keeps one value from start to end (the number of days in a week). A **variable** is a named store whose value can change: the program puts a value in, reads it, and replaces it as the work demands. **Data** is the book's word for the values themselves — the material constants and variables hold.
2. **Naming rules and data types** — A variable's **name** is under rules: it must begin with a letter, may join letters, digits and underscore into one word, takes no spaces, and must not be one of the language's own reserved words. Names are chosen to say what the variable holds. Values themselves have **types** — above all **numbers** and **text (strings)** — and the type decides what may be done with the value: numbers can be calculated with; text can be joined and compared. Mongolia's discipline: name the quantity, fix its type in your mind, and only then write the program that uses it.
