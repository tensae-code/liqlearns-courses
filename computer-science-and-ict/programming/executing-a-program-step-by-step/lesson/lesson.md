# Executing a Program Step by Step

## Do it first

A program lies written on the board. Nobody presses run. Instead, the class will BE the machine: read one instruction, do exactly that, say the new state aloud. Before reading on, guess which instruction will cause the argument.

## Sub lesson 1 — One instruction, one state

**Executing** a program means carrying out its instructions **in order**, each one changing the **state** — where things are, what values hold. The séance executes the class's first Square CT program **together (ensemble)**: one voice reads the instruction, hands perform it, another voice states the resulting state before anyone may read on. The discipline — no skipping, no assuming — is the machine's own, practised by people.

In your mind's eye: one instruction, one state.

## Sub lesson 2 — Why execute by hand first

Hand execution is the programmer's microscope: it shows **what the program actually says**, as opposed to what its writer meant — the gap where bugs live. A class that has executed together can predict a program's behaviour before running it, and when the machine later surprises them, they can replay the execution to find the step where paper and machine part ways. Prediction first, machine second: that order is the séance's whole gift.
