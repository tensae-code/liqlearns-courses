# Common file extensions — the full table

## Do it first

You already know four endings. Write down every other ending you have ever seen at the end of a filename — on a school computer, a phone, anywhere. Keep the list beside you. This lesson gives you the full table to check it against.

## The full table

[Picture 14104 — the full extension table]

Read the table row by row. Each row pairs a file type with its extension and what the file holds:

- **.txt** — simple text
- **.doc / .docx** — Word document
- **.rtf** — rich text
- **.pdf** — portable document
- **.ppt** — presentation
- **.xls / .xlsx** — spreadsheet
- **.mdb** — Access database
- **.zip / .rar** — compression (a squeezed file — the Compressing lesson teaches it)
- **.exe** — a self-extracting program
- **.mp3 / .wav** — audio

Learn the rows in pairs that travel together: the two Word endings, the two spreadsheet endings, the two compression endings, the two audio endings.

## How long may an extension be?

The rules differ by system, and the difference matters:

- In **Unix**, an extension is **optional** — a file may carry none.
- In **Linux and Windows**, an extension is **required**.
- **DOS** allows **three** characters.
- **Windows** allows **three or four**.
- **Unix-based systems** allow **unlimited** length.

So the same file may need its ending shortened or may keep a long one, depending on the system it moves to.

## Say it to your companion

Read one full row of the table to your companion — extension, file type, contents. Then state the length rules for DOS, Windows and Unix-based systems without looking.
