# Lesson plan — What a file is

**Course:** Computer Science and ICT · **Title:** Files and Folders · **Lesson:** What a file is
**Place in the curriculum:** Unit 1 — Organization of Files — in the title Files and Folders on the ICT course ladder (TITLES.md).
**The one thing this lesson teaches:** A file is a collection of data stored as one unit under a filename — a document, picture, text, video or audio — shown on screen by an icon that tells its type at a glance.
**This lesson's own level:** It stands on nothing but the learner's own computer or phone: everyone has opened a file. It is the first lesson of Unit 1, and it carries the whole Grade 9 course road map.

A lesson plan also says **what goes on top of the lesson**: at the exact places marked below, the lesson page carries an add-on — an image, a GIF, a video, an audio. Every slot is written as **"a picture of …" in words, plus one little line saying what the student does with it**. The words carry the picture while the course is built and while the AI learns from the books; on the website the real add-on is dropped into that slot and the little explanation stays as the student's guide. GIFs come first where a thing must be shown moving — a GIF here is 1–2 seconds.

## Sub lessons
The parts of this lesson, in order — the list the learner sees from the start, locked ahead, each opening when the one before it is proved:

1. **What a file is** — a collection of data stored as one unit under a filename; its icon differs by type and program.
2. **Telling file types by their extensions (teacher guide — evidence)** — the drill the guide adds: .docx a Word document, .pptx a PowerPoint file, .xlsx a spreadsheet, .mp3 an audio file, .mp4 a video file.
3. **The road ahead — six units, and how each unit runs** — the course road map from files to first flowcharts and Scratch scripts, and the brainstorm-first rhythm every unit follows.

Gate pool: all questions of the sub lesson — no hardness ranking is written in questions/, so the sub lesson's whole question set is the gate pool.

## Before this lesson
- Recommended first: nothing before it in this title — it opens Unit 1. Recommended, never forced — a learner may land on this lesson directly, and it stands alone.

## What the learner can do when it ends
1. Say what a file is: a collection of data stored as one unit under a filename.
2. Tell a document, picture, text, video and audio file apart by the icon on screen.
3. Read an extension — .docx, .pptx, .xlsx, .mp3, .mp4 — and say what kind of file it names (teacher guide — evidence).
4. Name the six units of the course in order, from organizing files to first flowcharts and Scratch scripts.

## What you need
A computer or phone with some files on it. Paper and a pencil.

## The run of the lesson (in order)
1. **Do it first** — Look at your own desktop or phone screen first and name every different kind of file you can see — before any definition is given. This is the brainstorm the book opens with: start from what you already know, like the membership file of an edir or an ekub you already keep on paper. (lesson/lesson.md).

## If the learner is stuck
Calls the icon the file → the icon only stands for the file on screen; the file itself is the data stored as one unit under its filename. Mixes the extension kinds → drill the five in pairs: .docx/.pptx/.xlsx are documents you make, .mp3 you hear, .mp4 you watch.
