# Import and export — data in, data out

## Do it first

A marks file is downloaded from the internet. It must end up inside a spreadsheet, as rows and columns you can calculate with. Then, later, the finished spreadsheet must leave the program as a plain file another program can read. Two journeys, opposite directions. This lesson names both.

## In and out

**Importing** moves files or data from one program into another — bringing information **in**. The worked example: a downloaded **CSV** file — a text file whose values are separated by commas — is brought **into** an Excel spreadsheet, where its comma-separated values become the sheet's rows and columns.

[Picture 14109 — import in, export out]

**Exporting** moves information **out** of a program into a file. The reverse example: the spreadsheet is exported **to CSV** — the same comma-separated text form it arrived in.

Exporting is done from the program's **File menu**, choosing the target format. Common export formats named here include **.txt, .bmp, .jpg and .gif**. And the same in-and-out works for notes: notes exported from OneNote come out as **.doc** files.

Hold the pair by direction and the words never swap: import brings in; export sends out.

## Say it to your companion

Tell your companion the whole round trip: the CSV file's journey into the spreadsheet, and the spreadsheet's journey back out to CSV. Name the menu exporting is done from.

## Do It Yourself

1. Download or write a small CSV file — three names, three marks, commas between. Import it into a spreadsheet and check the values land in separate columns.
2. Change one mark in the sheet. Export the sheet to CSV. Open the CSV as text: is your changed mark there?
3. List the four common export formats named in this lesson from memory.
