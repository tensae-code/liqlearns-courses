# Lesson plan — Developing an Information System — the Four Stages

**Course:** Computer Science and ICT · **Title:** Computers in Society · **Lesson:** Developing an Information System — the Four Stages
**Place in the curriculum:** ICT expansion — China (2026-11-14) — in the title Computers in Society on the ICT course ladder (TITLES.md). Built new from China's *IT Compulsory 2*, because no existing lesson in the course covers this thing as its own lesson.
**The one thing this lesson teaches:** An information system is not bought off a shelf and switched on — it is developed in four stages in order: planning (is it needed, and can it be done?), analysis (what exactly must it do?), design (the blueprint of how it will do it), and implementation (build it, test it, and change over to it).
**This lesson's own level:** It stands on the lessons about what an information system is and its five components. The learner needs no programming before it — this is the road map every system travels before code is written.

A lesson plan also says **what goes on top of the lesson**: at the exact places marked below, the lesson page carries an add-on — an image, a GIF, a video, an audio. Every slot is written as **"a picture of …" in words, plus one little line saying what the student does with it**. The words carry the picture while the course is built and while the AI learns from the books; on the website the real add-on is dropped into that slot and the little explanation stays as the student's guide. GIFs come first where a thing must be shown moving — a GIF here is 1–2 seconds.

## Sub lessons
The parts of this lesson, in order — the list the learner sees from the start, locked ahead, each opening when the one before it is proved:

1. **Stage one and two — planning and analysis** — **Stage 1: Planning.** The work starts by investigating the present situation: what problem is hurting, what the organisation hopes a system will fix, and whether a new system is **feasible** — possible with the money, people, time and technology actually available. Planning ends with a decision: go ahead, or not yet.
2. **Stage three and four — design and implementation** — **Stage 3: Design.** Now the *how* is drawn, as a blueprint: what data is stored and in what structure, what processes turn inputs into outputs, what the screens and printed reports look like, and how the parts connect. Nothing is built yet — design mistakes are cheap on paper and expensive in code.

Gate pool: all questions of the sub lesson — no hardness ranking is written in questions/, so the sub lesson's whole question set is the gate pool.

## What the learner can do when it ends
1. Name the four stages of developing an information system, in order.
2. Say what question each stage answers: planning — is it needed and feasible? analysis — what must it do? design — how will it do it? implementation — build, test, change over.
3. Explain why analysis fixes requirements before design begins.
4. Walk a real example (a school attendance system) through all four stages.

## What you need
Paper and a pencil.

## The run of the lesson (in order)
1. **Do it first** — Imagine your school decides to replace its paper attendance registers with a computer system. Nobody starts by typing code. First someone asks: do we really need this, and can we afford it? Then: what exactly must it record? Then: how will the screens and records look? Only then is it built. Those four questions, in that order, are this lesson. (lesson/lesson.md).

## If the learner is stuck
Mixes up analysis and design → analysis says WHAT the system must do; design says HOW. If a sentence names a screen layout or a data structure, it is design; if it names a need, it is analysis. Thinks testing is optional → testing checks the built system against the requirements written in analysis; skipping it means nobody knows whether the promises were kept.
