## Sub lessons
The parts of this lesson, in order — the list the learner sees from the start, locked ahead, each opening when the one before it is proved:

1. **The problem shape — need, choice, application** — A cipher problem states a **situation with a secrecy need**: a message must travel through hands that must not read it, and arrive readable by its one intended reader. Solving follows the unit's whole chain: state the need (how secret, how long, whose hands), **choose** the method by the need, **apply** it exactly (encrypt letter by letter with the chosen key or table), and hand over ciphertext plus — by a separate safe path — the key.
2. **Checking the solution — decrypt and judge** — The solution is **checked from the reader's end**: the intended reader decrypts with the key and must recover the plaintext **exactly** — one wrong letter means the application, not the idea, failed, and the encryption is reworked. Then the solver judges the holding: could an unintended hand, with the time the secret must last, break this method? If yes, the choice was wrong for the need and the problem is solved again with a stronger method. Malaysia's problems end with that judgement written down — a cipher solution is a claim, and the claim must be examined.

Gate pool: all questions of the sub lesson — no hardness ranking is written in questions/, so the sub lesson's whole question set is the gate pool.

## What the learner can do when it ends
1. A situation with a secrecy need — a message that must travel unreadable and arrive readable by one reader
2. State the need, choose the method, apply it exactly, hand over ciphertext and key by separate paths
3. By a separate safe path — never with the ciphertext
4. From the reader's end — decrypt and recover the plaintext exactly
