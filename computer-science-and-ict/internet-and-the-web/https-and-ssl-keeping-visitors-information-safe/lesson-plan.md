# Lesson plan — HTTPS and SSL — how a site keeps visitors' information safe

**Course:** Computer Science and ICT · **Title:** Internet and the Web · **Lesson:** HTTPS and SSL — how a site keeps visitors' information safe
**Place in the curriculum:** Title — Internet and the Web in the Computer Science and ICT ladder (TITLES.md); stocked from Ethiopia's Grade 12 book, Unit 4 — Web Authoring. The ladder is the recommended order, never a forced one.
**The one thing this lesson teaches:** a site that takes private information needs HTTPS, not HTTP: the secure transfer protocol, enabled by an SSL certificate that encrypts information in transit — and a visitor checks it by the padlock, or the 'Not secure' warning, in the address bar.
**This lesson's own level:** it stands on the publishing run — the learner can publish and name a site; this doing lesson secures it, and teaches the check every visitor can make.

## Sub lessons
The parts of this lesson, in order — the list the learner sees from the start, locked ahead, each opening when the one before it is proved:

1. **HTTPS and SSL — the secure connection (doing)** — if visitors give private information, a site needs HTTPS, the secure transfer protocol, enabled by an SSL certificate; SSL provides the secure connection and encrypts information in transit between the website and its database
2. **The visitor's check — padlock or 'Not secure' (doing)** — a secure site shows a locked padlock in the address bar; an insecure one shows an information icon and "Not secure"

Gate pool: all questions of the sub lesson — no hardness ranking is written in questions/, so the sub lesson's whole question set is the gate pool.

## Before this lesson
- Recommended first: Hosting and domain names — putting a site on a server. Recommended, never forced.

## What the learner can do when it ends
1. Say when a site needs HTTPS: when visitors give private information.
2. Say what SSL does: secure connection, encrypted in transit between website and database.
3. Check any site in the address bar: padlock, or 'Not secure'.

## What you need
A computer with a browser, for the address-bar check.

## If the learner is stuck
- Trusts a site because it looks professional → looks prove nothing; the address bar's padlock is the check.
- Confuses the two protocols' names → HTTPS is the secure one; the S is the whole difference.
