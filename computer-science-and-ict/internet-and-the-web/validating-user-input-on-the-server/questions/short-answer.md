# Validating User Input on the Server — short answer

Answer in a short sentence of your own.

**1. (Sub lesson 1) What is validation?**
**Answer: Checking a sent value against its rules before the program uses or stores it**

**2. (Sub lesson 1) Name the standing checks.**
**Answer: Presence, type, range, format, length**

**3. (Sub lesson 1) A mark of 140 fails which check?**
**Answer: Range — a mark must lie between 0 and 100**

**4. (Sub lesson 1) An email without its shape fails which check?**
**Answer: Format**

**5. (Sub lesson 1) How are failures reported?**
**Answer: To the user, by field — so the sending can be corrected**

**6. (Sub lesson 2) Why is a bare 'invalid' worthless?**
**Answer: It teaches nothing and protects by luck**

**7. (Sub lesson 2) Why is the server's check the one that counts?**
**Answer: The page's code runs in the visitor's browser — skippable, alterable, bypassable**

**8. (Sub lesson 2) Must a sender ever load your page?**
**Answer: No — data can be sent without it**

**9. (Sub lesson 2) What is Malaysia's architecture?**
**Answer: Both — the client checks for the user's sake; the server checks for the data's sake**

**10. (Sub lesson 2) What do this unit's stored files hold?**
**Answer: Only what the server's gate let through**
