# Lesson plan — DTD — the rulebook inside the document

**Course:** Computer Science and ICT · **Title:** Internet and the Web · **Lesson:** DTD — the rulebook inside the document
**Place in the curriculum:** Title — Internet and the Web in the Computer Science and ICT ladder (TITLES.md); stocked from Ethiopia's Grade 12 book, Unit 4 — Web Authoring. The ladder is the recommended order, never a forced one.
**The one thing this lesson teaches:** a DTD defines a document's structure and its legal elements and attributes so an application can verify the data is valid; an internal DTD sits inside the file, wrapped in the DOCTYPE — read line by line through the album example.
**This lesson's own level:** it stands on the declaration-and-DTD lesson and the entities lesson — the learner has met DOCTYPE and internal declarations; this doing lesson reads a complete DTD as a rulebook and checks a document against it.

A lesson plan also says **what goes on top of the lesson**: at the exact places marked below, the lesson page carries an add-on — an image, a GIF, a video, an audio. GIFs come first where a thing must be shown moving or in steps — a GIF here is 2 seconds.

## Sub lessons
The parts of this lesson, in order — the list the learner sees from the start, locked ahead, each opening when the one before it is proved:

1. **What a DTD is — and where it sits (doing)** — a DTD defines a document's structure and its legal elements and attributes, so an application can verify XML data is valid; an internal DTD sits inside the XML file wrapped in the DOCTYPE definition
2. **The album DTD, line by line (doing)** — DOCTYPE names the root (album); album must contain singer, name, release and language in order; each of those is declared as #PCDATA

Gate pool: all questions of the sub lesson — no hardness ranking is written in questions/, so the sub lesson's whole question set is the gate pool.

## Before this lesson
- Recommended first: Parts of an XML document — declaration and DTD; Entities — declare once, reference by name. Recommended, never forced.

## What the learner can do when it ends
1. Say what a DTD defines and what an application does with it.
2. Read the album DTD line by line: root, order, #PCDATA leaves.
3. Check a document against its DTD and call it valid or not, with the broken rule named.

## What you need
Paper and a pencil; a computer with a text editor helps.

## If the learner is stuck
- Checks content instead of structure → the DTD rules on structure and legal elements/attributes, not on whether the singer is good.
- Forgets the order → the album's four parts must come in the declared order: singer, name, release, language.
