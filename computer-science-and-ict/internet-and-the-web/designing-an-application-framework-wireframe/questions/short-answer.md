# Designing an Application Framework (Wireframe) — short answer

Answer in a short sentence of your own.

**1. (Sub lesson 1) What is a wireframe?**
**Answer: A skeleton drawing of one page — boxes for its regions, labels for what each holds**

**2. (Sub lesson 1) Name the usual regions.**
**Answer: Banner, menu, content, footer**

**3. (Sub lesson 1) What does a wireframe leave out?**
**Answer: Decoration — no colours, fonts or images beyond placeholders**

**4. (Sub lesson 1) How many wireframes are drawn?**
**Answer: One per page, in the same skeleton style**

**5. (Sub lesson 1) Why the same style?**
**Answer: So pages can be compared and shared furniture checked for sameness**

**6. (Sub lesson 2) What completes the framework?**
**Answer: The joins — each page's links drawn to their target pages**

**7. (Sub lesson 2) The whole site stands as what?**
**Answer: A map a builder can follow and a client can judge**

**8. (Sub lesson 2) Name the review's three checks.**
**Answer: Every promised page present; every link landing somewhere real; no orphan page**

**9. (Sub lesson 2) When does building begin?**
**Answer: Only after the framework review passes**

**10. (Sub lesson 2) What does a framework fault found in code cost?**
**Answer: The rebuild the drawing exists to prevent**
