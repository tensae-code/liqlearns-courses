# Lesson plan — Image links — and absolute vs relative URLs

**Course:** Computer Science and ICT · **Title:** Internet and the Web · **Lesson:** Image links — and absolute vs relative URLs
**Place in the curriculum:** Title — Internet and the Web in the Computer Science and ICT ladder (TITLES.md); stocked from Ethiopia's Grade 11 book, Unit 4 — Web Development. The ladder is the recommended order, never a forced one.
**The one thing this lesson teaches:** an image placed between an anchor's tags becomes the clickable part of a link — and an address can be written absolute, with every part, or relative to the current page.
**This lesson's own level:** it stands on the links lesson — the anchor's clickable part changes from text to an image.

A lesson plan also says **what goes on top of the lesson**: at the exact places marked below, the lesson page carries an add-on — an image, a GIF, a video, an audio. Every slot is written as **"a picture of …" in words, plus one little line saying what the student does with it**. The words carry the picture while the course is built and while the AI learns from the books; on the website the real add-on is dropped into that slot and the little explanation stays as the student's guide. GIFs come first where a thing must be shown moving or in steps — a GIF here is 2 seconds.

2. **Absolute and relative URLs** — the two ways of writing an address, and when the relative form is used

1. Make an image into a link.
2. Tell an absolute URL from a relative URL.
3. Use a relative address for a file in the page's folder.

## If the learner is stuck
- Image shows but does not click → the image element must sit between the anchor's start and end tags, not beside them.
- Relative address fails → a relative path is measured from the current page's location; it works when the file is where the path says, e.g. the same folder.
