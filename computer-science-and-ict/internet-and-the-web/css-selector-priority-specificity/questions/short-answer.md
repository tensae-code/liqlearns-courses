# CSS Selector Priority — Which Rule Wins — short answer

Answer in a short sentence of your own.

**1. (Sub lesson 1) What settles a fight between CSS rules?**
**Answer: Priority — specificity: the more specific selector wins**

**2. (Sub lesson 1) What beats every selector?**
**Answer: An inline style, written in the element's style attribute**

**3. (Sub lesson 1) Order the three selector kinds by priority.**
**Answer: Id highest, then class, then element**

**4. (Sub lesson 1) A class says blue, an element rule says black — which wins?**
**Answer: The class rule — blue**

**5. (Sub lesson 1) Why does the book end the CSS strand here?**
**Answer: Because until you can predict the winning rule, styling is guessing**

**6. (Sub lesson 2) Two rules have equal priority — which wins?**
**Answer: The later rule in the stylesheet**

**7. (Sub lesson 2) In what order should styles be written?**
**Answer: Elements generally first, then classes, ids sparingly, inline styles almost never**

**8. (Sub lesson 2) Why are inline styles a trap?**
**Answer: They cannot be overridden, so they fight every later design change**

**9. (Sub lesson 2) How do you debug a wrong colour?**
**Answer: Find every rule touching the element and climb the priority ladder**

**10. (Sub lesson 2) What is the cascade?**
**Answer: CSS's order of reading and settling rules — the flow that gives the style sheets their name**
