# Lesson plan — XML attributes and comments

**Course:** Computer Science and ICT · **Title:** Internet and the Web · **Lesson:** XML attributes and comments
**Place in the curriculum:** Title — Internet and the Web in the Computer Science and ICT ladder (TITLES.md); stocked from Ethiopia's Grade 12 book, Unit 4 — Web Authoring. The ladder is the recommended order, never a forced one.
**The one thing this lesson teaches:** an element can carry attributes — quoted name-value pairs giving more information about it — and comments, notes the parser ignores.
**This lesson's own level:** it stands on the root-and-elements lesson — the learner can take an element apart; this lesson adds the two things that ride on an element without being its content.

A lesson plan also says **what goes on top of the lesson**: at the exact places marked below, the lesson page carries an add-on — an image, a GIF, a video, an audio. Every slot is written as **"a picture of …" in words, plus one little line saying what the student does with it**. The words carry the picture while the course is built and while the AI learns from the books; on the website the real add-on is dropped into that slot and the little explanation stays as the student's guide. GIFs come first where a thing must be shown moving or in steps — a GIF here is 2 seconds.

## Sub lessons
The parts of this lesson, in order — the list the learner sees from the start, locked ahead, each opening when the one before it is proved:

1. **Attributes — a name-value pair on an element** — an attribute gives additional information about an element; its value must be quoted in single or double quotes
2. **Comments — notes the parser ignores** — a comment describes the code, is ignored by the XML parser while the code runs, and uses the HTML-style comment markers

Gate pool: all questions of the sub lesson — no hardness ranking is written in questions/, so the sub lesson's whole question set is the gate pool.

## Before this lesson
- Recommended first: Root, elements and data — the XML tree. Recommended, never forced.

## What the learner can do when it ends
1. Say what an attribute is and write one, quoted.
2. Say what a comment is, how it is written, and what the parser does with it.

## If the learner is stuck
- Leaves the attribute value unquoted → the value must be quoted, in single or double quotes.
- Expects the comment to appear in the output → the parser ignores comments while the code runs.
