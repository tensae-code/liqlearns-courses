# Hosting and domain names — putting a site on a server

## Do it first

Watch the GIF: your files travel up an arrow and land on a machine that is not yours. The site is live — but how will anyone find it? It needs a name, and that name must be claimed before someone else takes it. This lesson names all three steps: the host, the server, the name.

## Sub lesson 1 — Hosting — uploading to the host's server

A site is published by **uploading its files to the remote server of a hosting company — a web host**. The host **provides online storage space**: you build the site, the host gives it a machine to live on.

The **web server** is **the actual machine where the site resides**. One server may host **one or many sites**, depending on the service paid for — your site may have a whole machine, or neighbours, by the terms of the hosting you bought. ## Sub lesson 2 — Registering a domain name

Publishing also involves **registering a domain name** — **the part of the address after "www"**. In the ministry address example, the domain name as printed is **"moe.gov"**.

The domain name **becomes the site's online address**, so choose it well:

- It should be **easy to remember and easy to type** — it is the address every visitor must use.
- It must be **unique**. **If it is taken, registration fails**, and another name must be found.

Host, server, name: with all three, a built site becomes a published site that the public can reach.
