# Lesson plan — Root, elements and data — the XML tree

**Course:** Computer Science and ICT · **Title:** Internet and the Web · **Lesson:** Root, elements and data — the XML tree
**Place in the curriculum:** Title — Internet and the Web in the Computer Science and ICT ladder (TITLES.md); stocked from Ethiopia's Grade 12 book, Unit 4 — Web Authoring. The ladder is the recommended order, never a forced one.
**The one thing this lesson teaches:** an XML document's content parts — one root enclosing everything, start and end tags, elements, and the data between tags — form an upside-down tree.
**This lesson's own level:** it stands on the declaration-and-DTD lesson — the learner has read a document's top; this lesson reads its content and draws its shape.

A lesson plan also says **what goes on top of the lesson**: at the exact places marked below, the lesson page carries an add-on — an image, a GIF, a video, an audio. Every slot is written as **"a picture of …" in words, plus one little line saying what the student does with it**. The words carry the picture while the course is built and while the AI learns from the books; on the website the real add-on is dropped into that slot and the little explanation stays as the student's guide. GIFs come first where a thing must be shown moving or in steps — a GIF here is 2 seconds.

## Sub lessons
The parts of this lesson, in order — the list the learner sees from the start, locked ahead, each opening when the one before it is proved:

1. **Content, root, tags, elements, data** — the content / information set, the single root, the matching start and end tags, the element as building block, and the data between tags
2. **The upside-down tree — and what XML still needs** — root containing sub-elements containing further sub-elements and data forms a hierarchy drawn as an upside-down tree; XML plus other resources becomes a finished document

Gate pool: all questions of the sub lesson — no hardness ranking is written in questions/, so the sub lesson's whole question set is the gate pool.

## Before this lesson
- Recommended first: Parts of an XML document — declaration and DTD. Recommended, never forced.

## What the learner can do when it ends
1. Name the content parts: content, root, start tag, end tag, element, data.
2. Draw a document as an upside-down tree.
3. Say why XML alone is not a finished document.

## If the learner is stuck
- Draws two roots → a document has a single root element enclosing everything.
- Mixes element and tag → an element runs from its start tag to its end tag; the tags are its two ends.
