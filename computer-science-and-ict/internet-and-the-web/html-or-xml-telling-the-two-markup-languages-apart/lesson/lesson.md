# HTML or XML? Telling the two markup languages apart

## Do it first

Twelve claims: 'errors are tolerated', 'tags are your own', 'files end .htm', 'case matters', 'closing tags are essential'… Sort them: HTML, XML, or both? This lesson lays the full comparison out, row by row, so every claim finds its column.

## Sub lesson 1 — What each language is, and what it is for

The identity rows of the comparison:

- **Language type:** XML is a **framework for specifying markup languages**; HTML is a **predefined markup language**.
- **Structural details:** **provided by XML, not by HTML**.
- **Purpose:** XML is for the **transfer of data**; HTML is for **display / presentation**.
- **Driven by:** XML is **content**-driven; HTML is **format**-driven.
- **Tags:** XML's are **custom-defined**; HTML's are **predefined**.
- **Extensions:** XML files end **.xml**; HTML files end **.html / .htm**.
- **Size:** XML documents are **mostly lengthy**; HTML syntax is **brief**.
- **Learning curve:** XML is **hard** — XPath, XML Schema and DOM are also to learn; HTML is a **simple, familiar stack**.

## Sub lesson 2 — Where XML is strict and HTML is loose

The strictness rows:

- **Nesting:** in XML it **must be proper**; in HTML, **improper nesting has no effect**.
- **Coding errors:** in XML, **none are allowed**; in HTML, **small errors are ignored**.
- **Whitespace:** XML **keeps** it; HTML collapses it (the earlier lesson's rule, sitting in its row here).
- **Case sensitivity:** XML is **sensitive**; HTML is **not**.
- **Closing tags:** **essential** in XML; **not always required** in HTML.
- **Attribute quoting:** **required** in XML; **not required** in HTML.

The pattern across all six rows is one sentence: **XML holds its documents to the rules; HTML lets small slips pass.**
