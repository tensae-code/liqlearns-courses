## Sub lessons
The parts of this lesson, in order — the list the learner sees from the start, locked ahead, each opening when the one before it is proved:

1. **Building up and updating — the store at work** — Data is **built up** as records arrive — appended by the programs of this unit, each validated before it is stored. It is **updated** when the world changes: a record is **found** (by its key — a name, an ID), its fields **corrected**, and the store **rewritten** with the correction in place; a record that should no longer exist is **removed** the same careful way. With text-file storage, updating means the program reads the records, changes the one, and writes the set back — which is why updates are done by program, never by hoping a hand edit kept the format.
2. **Backing up — the copy that outlives the accident** — A **backup** is a **copy of the whole store**, made regularly and kept **apart** from the working copy — another folder, another device — so that the accident that takes one does not take both. Backing up web data in this unit means copying the text files on a rhythm (after each day's work, each week) and **testing** that a copy can actually be read back: an untested backup is a hope, not a backup. Malaysia's close is the duty stated plainly: data kept for others is a trust; building it carefully and then losing it for want of a copy is the one fault this unit calls unforgivable.
