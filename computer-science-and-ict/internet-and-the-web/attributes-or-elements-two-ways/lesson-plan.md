# Lesson plan — Attributes or elements? Carrying the same information two ways

**Course:** Computer Science and ICT · **Title:** Internet and the Web · **Lesson:** Attributes or elements? Carrying the same information two ways
**Place in the curriculum:** Title — Internet and the Web in the Computer Science and ICT ladder (TITLES.md); stocked from Ethiopia's Grade 12 book, Unit 4 — Web Authoring. The ladder is the recommended order, never a forced one.
**The one thing this lesson teaches:** the same information can be carried as an attribute on an element or as a child element — a quoted name-value pair against a nested element — and XML has no rule for when to use which.
**This lesson's own level:** it stands on the attributes lesson and the naming lesson — the learner can write both forms; this lesson puts them side by side on the same information.

## Sub lessons
The parts of this lesson, in order — the list the learner sees from the start, locked ahead, each opening when the one before it is proved:

1. **Attributes — the pair, and the quote rescue** — an attribute is a key-value pair on an element, its value always quoted in single or double quotes; if the value itself contains double quotes, single quotes are used instead
2. **The same information, two ways — and no rule** — gender stored once as an attribute on a person element and once as a child element; XML has no rule for when to use attributes versus elements

Gate pool: all questions of the sub lesson — no hardness ranking is written in questions/, so the sub lesson's whole question set is the gate pool.

## Before this lesson
- Recommended first: XML attributes and comments; Naming XML elements — and empty elements. Recommended, never forced.

## What the learner can do when it ends
1. Write the same information as an attribute and as an element.
2. Handle a value containing double quotes by switching to single quotes.
3. State that XML has no rule for attributes versus elements.
