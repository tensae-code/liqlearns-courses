# XML — strengths and weaknesses

## Do it first

You have spent a run of lessons inside XML. Two columns, from your own experience: what was it good for? What cost you effort? This lesson weighs your lists against the official table — strengths on one side, weaknesses on the other.

## Sub lesson 1 — Advantages — data that travels

The advantages, as weighed:

- XML documents are **transportable across systems and applications**, and **data exchanges quickly between platforms**.
- XML **separates data from HTML** — the data stands on its own, not tangled into a page's presentation.
- It **simplifies the platform-exchange process** — moving data from one platform to another is a simpler job with XML carrying it.

One theme runs through the list: XML's strength is **movement** — data that can travel, be exchanged, and arrive still structured.

## Sub lesson 2 — Disadvantages — the costs (and one bullet that is wrong)

The real disadvantages:

- XML **requires a processing application** — by itself, as you know, it does nothing.
- Its syntax is **very similar to other text-based data-transmission formats** and **can be confusing**.
- It has **no intrinsic data-type support** — the data types are not built in.
- Its syntax is **redundant** — opening and closing tags repeat the same names, and documents grow long.

Hold one warning with this list. A table of disadvantages somewhere claims XML 'does not allow users to create their tags'. **That is false** — creating your own tags is the first thing this whole run of lessons taught, and it is XML's whole point. Wherever you meet that bullet, treat it as an error, not a fact.
