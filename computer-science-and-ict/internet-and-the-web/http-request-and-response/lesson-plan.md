# Lesson plan — HTTP — how a web page is requested and delivered

**Course:** Computer Science and ICT · **Title:** Internet and the Web · **Lesson:** HTTP — how a web page is requested and delivered
**Place in the curriculum:** Title 8 — Internet and the Web of the Computer Science and ICT ladder (TITLES.md); Ethiopia Grade 8, Unit 4 — Internet. The ladder is the recommended order, never a forced one.
**The one thing this lesson teaches:** HTTP — Hypertext Transfer Protocol — is the request-and-response protocol of the Web: the browser (client) asks, the connection is made through TCP, the server picks the data, and HTTP carries the response — the page — back at once.
**This lesson's own level:** it stands on the Web lesson and the web-address lesson — the learner knows pages have URLs beginning with http; this lesson shows what those letters do.

A lesson plan also says **what goes on top of the lesson**: at the exact places marked below, the lesson page carries an add-on — an image, a GIF, a video, an audio. GIFs come first where a thing must be shown moving — a GIF here is 2 seconds, looping.

## Sub lessons
The parts of this lesson, in order — the list the learner sees from the start, locked ahead, each opening when the one before it is proved:

1. **The round trip — request, connection, data, response** — HTTP is a request–response protocol: the client requests, the connection is made through TCP, the server picks the data from its database, and HTTP sends the response back; it also formats and transfers page data
2. **HTTP beside SMTP — and two more protocols named** — HTTP is likened to SMTP but differs in how messages are sent: HTTP messages are not read by humans and are delivered immediately; SMTP messages are stored and forwarded; IMAP and NTP are also named

Gate pool: all questions of the sub lesson — no hardness ranking is written in questions/, so the sub lesson's whole question set is the gate pool.

## Before this lesson
- Recommended first: The Web — pages, websites, hyperlinks and URLs (the grown Web lesson). Recommended, never forced. A learner can land here directly; the lesson stands alone.

## What the learner can do when it ends
1. Say what HTTP stands for and what it is used for.
2. Tell the round trip in order: request, connection through TCP, data picked from the database, response back.
3. Name the client and the server.
4. Tell HTTP from SMTP: immediate delivery against stored and forwarded.

## If the learner is stuck
- Thinks the server sends pages unasked → nothing travels until the client sends a request; the response answers the request.
- Mixes client and server → the client asks (your browser); the server holds the data and answers (the web host).
