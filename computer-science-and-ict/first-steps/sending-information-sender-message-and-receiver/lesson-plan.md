## Sub lessons
The parts of this lesson, in order — the list the learner sees from the start, locked ahead, each opening when the one before it is proved:

1. **Sender, message, receiver** — Every transmission has the same skeleton: a **sender (émetteur)** who has something to pass on, a **message** that travels, and a **receiver (récepteur)** who must rebuild the meaning at the other end. Pixel paravent plays it with a screen (paravent) between two pupils: the sender sees a black-and-white picture and may only send agreed signals; the receiver, who cannot see the picture, must rebuild it square by square.
2. **The shared language makes it work** — The game only works because both sides share a **language in advance**: which signal means black, which means white, in what order the squares are read. Without the agreement, the same signals are noise. That is the deep lesson the activity carries into all computing: machines, like pupils, can only exchange information through a code both sides hold before the first signal is sent.

2. **The explanation** — the lesson text in lesson/lesson.md, in its parts in order.
