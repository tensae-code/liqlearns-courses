# Lesson plan — Driver software — letting devices talk to the operating system

**Course:** Computer Science and ICT · **Title:** Software · **Lesson:** Driver software — letting devices talk to the operating system
**Place in the curriculum:** Title 3 — Software in the Computer Science and ICT ladder (TITLES.md); stocked from Ethiopia's Grade 8 book, Unit 3 — Computer Software. The ladder is the recommended order, never a forced one.
**The one thing this lesson teaches:** a driver is software that controls a hardware device, letting it send and receive information so the device can communicate with the operating system.
**This lesson's own level:** it stands on the operating-system lesson — the driver is the go-between that lets a device and that operating system understand each other.

## Before this lesson
- Recommended first: System software and the operating system. Recommended, never forced.

## What the learner can do when it ends
1. Say what a driver is and what it controls.
2. Explain how a printer driver connects a printer to the operating system.
3. Name devices a driver controls: microprocessor, memory, hard drive and peripherals.
4. Say how modern computers connect to peripherals without physical connections.

## What you need
Paper and a pencil; a computer with a printer attached, if you can look at one.

## If the learner is stuck
- Thinks the printer plugs in and simply works by itself → something must translate between the device and the operating system; that something is the driver.
- Mixes driver with the device itself → the device is hardware you can touch; the driver is software that controls it.
