**Course:** Computer Science and ICT · **Title:** Software · **Lesson:** Integrating Information — Import and OLE Linking and Embedding
**Place in the curriculum:** ICT expansion — Mongolia (2026-11-14) — in the title Software on the ICT course ladder (TITLES.md). ## Sub lessons
The parts of this lesson, in order — the list the learner sees from the start, locked ahead, each opening when the one before it is proved:

1. **Import, link, embed — three ways to merge** — Merging information into a work is done three ways. **Importing** brings the other work's content in, converted, as the receiving program's own material — the tie to the source is cut at the door. **OLE linking** places the object so it **stays tied to its source file**: the work shows the object, and when the source changes, the work's copy follows — one truth, kept in one place. **OLE embedding** moves the object **into the work for good**: it travels with the document, editable there by its own program's tools, but cut off from the original — the source may change and the embedded copy will not know.
2. **The worked example — Bayankhongor in 24 slides** — The book's worked integration is a production: a **24-slide presentation on the sights of Bayankhongor aimag**, built by merging — texts, pictures, tables and media imported, linked and embedded from the programs that made them, into one presentable whole; the chapter's team project, **'My homeland tour'**, repeats the production for each team's own ground. Mongolia's judgement closes the topic: integration is chosen per part — link what must stay true, embed what must travel, import what must become native — and the worker who cannot name the three will merge by accident and maintain by sorrow.

Gate pool: all questions of the sub lesson — no hardness ranking is written in questions/, so the sub lesson's whole question set is the gate pool.
