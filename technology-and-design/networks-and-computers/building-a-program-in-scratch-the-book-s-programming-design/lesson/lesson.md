# Building a program in Scratch

## Do it first
Before reading on: take the materials this lesson names and try the task in your own way first. Then read how Malaysia's book teaches it, and compare.

## Sub lesson 1 — The Scratch workspace
Scratch is learned as a place first: the menu bar, the Sprite that acts, the Stage it acts on, the Tabs, the Blocks Palette of code blocks, and the Scripts Area where blocks join into a program. Features are used deliberately — moving an object, inserting dialogue, inserting sound, adding a new sprite.

## Sub lesson 2 — From plan to running code
The book builds sequence-control code from an algorithm and pseudocode — the plan becomes blocks — then runs the code, finds and fixes errors, and presents the project. Debugging is a named step, not an accident.

## Say it to your companion
Explain in your own words: in Scratch, an algorithm and pseudocode become joined blocks in the Scripts Area — run the code, fix its errors, present the project. Say it once plainly, then answer one question your companion asks about it.

## Do It Yourself
1. Do the Do it first task again, carefully this time, using everything the lesson taught.
2. Check your work against the lesson's own checks — fix one thing you find.
3. Keep your work: it is practice evidence, and the next lesson builds on it.
